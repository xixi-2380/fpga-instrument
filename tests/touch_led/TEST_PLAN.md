# AiP5916 全部按键无响应：分阶段排查方案

日期：2026-10-26。对应测试分支 `codex/touch-led-test`，程序基线 `2d3e898`。

目标：找出故障停在哪一层，依次证明“下载与 LED → 供电与接线 → I²C → 初始化 → 触摸键值 → INT → LED”。前一层没有证据，就先处理该层。

**现状只有“触摸后灯不亮”，尚未确认故障原因。本文件是测试方案，本次没有修改 RTL、生成新位流或操作下载器。** 下文标为“待补充诊断程序”的测试能力，当前版本没有提供。

## 1. 为什么当前一个灯不足以判断原因

现有 [touch_led_top.v](rtl/touch_led_top.v) 只有满足以下全部条件，才会点亮 LED：

```text
P16 时钟运行，K16 复位已释放
  → 等待约 20 ms
  → 25 项寄存器逐项写入和读回全部成功
  → init_ok = 1
  → U15 上的 INT 连续低约 1 ms
  → R26 输出低，LED1 亮
```

因此以下情况在外观上完全相同：LED 或下载不对、持续复位、芯片无电、地址无应答、某项读回错误、INT 断线、芯片未识别触摸。

还有两个排查时必须记住的行为：

- 任一事务失败后，程序停在 `FAILED`，不自动重试。修好接线后也需要按 **Dock USER_BUTTON0（K16）** 重新初始化。不要把核心板 USR（U4）当作本测试的复位。
- 若已写入 `SYSCON=0x5A`，但之后失败，没有成功写回 `0x00`，芯片可能仍在配置/深度睡眠模式，触摸扫描停止。**这会让所有键都没有响应，但不表示所有电极同时坏了。** FPGA 复位不是触摸芯片断电；需要时完整重启键盘与 FPGA，再检查初始化记录。

当前初始化后只看 INT，没有读 `0x34/0x35`。内部 `init_error` 也未接到 LED；部分内部调试信号可能被综合优化，不能假定现有网表已经能通过 GAO 观察到它们。

## 2. 先准备一套可重复的接线和记录

只接 **一块键盘板**，先不接 EC11、音频和其他同地址触摸板。保持短线、共地。上电及建立基线时手离开电极，先测裸板或当前固定覆盖层，不同时更换面板、改灵敏度和换线。

| 信号 | 键盘 J1 | FPGA 封装管脚 | AiP5916 SSOP24 管脚 |
|---|---:|---|---:|
| SDA | 3 | U16 | 22 |
| SCL | 5 | V16 | 21 |
| INT | 7 | U15 | 23 |
| 3.3V | 1 | 开发板电源，不能当 GPIO | 24，经过供电滤波 |
| GND | 2、4、6、8 | 开发板 GND | 1 |
| ADS | 板内接线 | 不连接新 GPIO | 3，当前设计接 VDD_TOUCH |
| C0 | 板内电容 | 不连接 GPIO | 4，10 nF 到地 |

J1 脚号依焊盘编号，不按排针照片的左右方向猜。**FPGA 的 U15 是封装坐标；触摸芯片 U1 的第 15 脚是 K12，二者不是一回事。** 上表只适用于 SSOP24，不套用 QFN24 引脚号。

记录下载文件路径、文件时间、源代码版本、实物芯片丝印、Dock 版本。下载文件应来自本测试的 `touch_led.gprj`，不是根目录 `keyboard_adsr.gprj` 的位流。下载工具显示成功只证明配置过程完成，不证明下载的是预期功能。

工具按现有条件选择：万用表先做第 3、4 节；有逻辑分析仪继续第 5、6 节；示波器用于核实电平和边沿。只有万用表时不能据平均电压认定 I²C 有 ACK，需要第 9 节的诊断程序补足状态。

## 3. T0：断电检查连通、方向和焊接

**操作条件：两块板都断电，拔掉外部供电后测电阻/通断。**

| 测试 | 预期与判据 | 异常时检查 |
|---|---|---|
| 开发板 GND 到键盘 J1 GND | 导通，扣除表笔电阻后接近 0 Ω | 地线和排针焊接 |
| FPGA 扩展口 U16 对应接点到 J1-3 | 导通 | 连接器编号、线插错、杜邦线 |
| V16 接点到 J1-5；U15 接点到 J1-7 | 分别导通，不互换 | 同上 |
| J1-3 到芯片 SDA22；J1-5 到 SCL21 | 按原理图经过约 510 Ω 串阻；不是要求蜂鸣器必响 | 漏焊、错阻值、断线或错误封装 |
| J1-1 到芯片 VDD24 | 按原理图经过约 22 Ω 滤波电阻 | 供电电阻漏焊/错值 |
| SDA、SCL 到 VDD_TOUCH 的上拉支路 | 原理图各有 10 kΩ；在板测量可能受其他支路影响 | 查装配值，不能因并联测量不恰好 10 kΩ 就判坏 |
| 芯片 ADS3 到 VDD_TOUCH | 当前设计应接高 | 桥接、焊盘方向、实际板是否改过地址 |
| 芯片 VDDA2 | 原厂允许接 VDD 或悬空，不能误当作 VSS 接地 | 封装方向、引脚编号与焊接 |
| C0 第 4 脚的 10 nF 电容及接地 | 核对实物值、焊接和网络 | 103=10 nF，不能把 104=100 nF 当作相同值 |
| VDD_TOUCH 对 GND | 排除持续近零的硬短路；电容充电导致读数变化不等于短路 | 锡桥、电容/芯片装反，先分离电源负载定位 |

用可接触的焊盘或测试点检查，避免表笔跨接细间距相邻脚。C0 是触摸参考电容，不是琴键；不要把它当按键刺激点。

**通过条件：供电和三根信号确实到达目标网络，串阻/上拉/参考电容与原理图一致。未通过先修连接，再进行下一步。**

## 4. T1：上电检查实际电平

万用表黑表笔固定在键盘板 GND。先测静态电源；测 SDA/SCL 空闲电平时，可按住 K16，让 FPGA 保持复位、释放总线。若不能确认下载的是本测试，先断开信号线单独检查键盘供电。

| 测点 | 调试目标 | 记录 |
|---|---|---|
| 键盘 J1-1 对 GND | 接近 3.3V | ___ V |
| 22 Ω 后 VDD_TOUCH / 芯片 VDD24 | 接近实际 3.3V；不应有明显异常压降 | ___ V |
| AiP5916 ADS3 | 接近 VDD_TOUCH，才符合当前 0x56 地址假设 | ___ V |
| J1-3 SDA，空闲 | 接近上拉电源，不能持续为低 | ___ V |
| J1-5 SCL，空闲 | 同上 | ___ V |
| 扩展口 SDA/SCL | 与芯片侧对照，定位串阻两侧差异 | ___ / ___ V |
| K16，按钮松开 / 按下 | 松开接近 3.3V，按下接近 0V | ___ / ___ V |
| INT：空手 / 触摸 / 松开 | 初始化正确且有有效触摸时，应高 / 低 / 高；此项还不能单独证明初始化成功 | ___ / ___ / ___ V |

这里的 3.3V 是接线调试目标，不是说芯片全部工作范围只有 3.3V。与 FPGA 连接时仍统一使用 3.3V，不能因为芯片允许其他电压就换成 5V。

**AiP5916 的 SCL/SDA/ADS 门限需要特别留意：** 原厂手册给出高电平至少 `0.8×VDD`、低电平至多 `0.2×VDD`。当芯片实际 VDD=3.3V 时，分别是 **≥2.64V、≤0.66V**。这不等于 INT 或 FPGA 输入的门限；其他电压按实测 VDD 重算。逻辑分析仪可能在更低门限就解码成 1，不能只凭“解码看起来正常”认定芯片也收到合格高电平。

异常处理：

- **芯片无电或滤波后明显偏低：** 先查供电、22 Ω 和焊接，不开始调灵敏度。
- **SDA/SCL 持续低：** 按住 K16、确认主机释放后复测；再断电分开 FPGA 与键盘的信号连接，分别检查短路、上拉和驱动来源。断线后只给一端供电时不要让信号反向给另一端灌电。
- **K16 松开仍低：** 本程序会一直复位，I²C 和触摸检测不会启动。先查按钮网络/管脚，而不是触摸芯片。
- **空闲电平只到约 1.8V：** 核查接错接口、上拉电源与实际 Bank VCCIO。CST 写 LVCMOS33 不会把真实 1.8V 电源变成 3.3V。

## 5. T2：单独证明下载、时钟和 LED

当前 LED 受 `init_ok` 门控，**不能用“不亮”证明 FPGA 没运行，也不能用强拉 INT 的办法绕过失败的初始化。**

此阶段建议增加一个独立的 `LED_SELFTEST` 模式，要求如下；**当前程序尚未实现该模式，不会自动出现这些灯效。**

1. 不访问触摸芯片，SDA/SCL 始终高阻释放。
2. 用 P16 的 50 MHz 直接计数，让 R26 对应的 LED1 每亮 0.5 秒、灭 0.5 秒。
3. 按 K16 保持复位，LED 回到约定灭灯状态；松开后重新闪烁。
4. 同一位流内先能强制 R26=0 点亮、R26=1 熄灭，再启用计数，区分灯号/极性与时钟问题。

| 结果 | 下一步 |
|---|---|
| 强制高低也不能控制目标灯 | 查下载对象、CST、实际观察的 LED、硬件连接 |
| 强制高低能控制，计数不闪 | 查 P16 时钟、复位、计数参数 |
| 能闪，但 K16 无法控制复位 | 查 K16 接线和实际按钮编号 |
| 闪烁和复位均正确 | 才把 LED 和系统时钟作为后续排查的已知条件 |

已有报告中的 PR1014 警告不是“触摸板坏了”的证据，也不能作为忽略时钟问题的理由。这里用实物闪烁/测钟单独验证。

## 6. T3：抓到第一笔 I²C，再找第一个失败点

### 6.1 接逻辑分析仪并抓启动

- CH0 接 SDA（U16 对应扩展口或 J1-3），CH1 接 SCL（V16/J1-5），CH2 接 INT（U15/J1-7）；分析仪 GND 接键盘 GND。探头应兼容 3.3V。
- 采样率可先用 5～10 MS/s，采集窗口约 100～200 ms，保证覆盖释放复位后的初始化。
- **先让分析仪开始等待，再松开 K16**。当前程序只启动一次，失败后线路会安静；事后再抓可能什么都看不到。
- 触发选 SDA 在 SCL 高时下降，或使用约 20 ms 以上预留窗口的启动采集。
- I²C 解码使用 7 位地址显示。`0x56 Write` 在线上等价于原始字节 `0xAC`；`0x56 Read` 等价于 `0xAD`，两种显示不是地址不一致。

### 6.2 第一笔应该是什么

按当前程序，第一笔写入是：

```text
START → AC → 从机ACK → 3A → 从机ACK → 5A → 从机ACK → STOP
```

随后马上读回同一寄存器：

```text
START → AC → 从机ACK → 3A → 从机ACK
      → 重复START → AD → 从机ACK → 读1字节 → 主机NACK → STOP
```

**写入/寻址后的 ACK 要看第 9 个 SCL 高电平时 SDA 是否低。读取最后一个字节之后的主机 NACK 则是正常结束，不是错误。**

| 捕获结果 | 可缩小到的范围 | 下一项证据 |
|---|---|---|
| 释放复位后完全无波形 | 未运行、持续复位、测错引脚、总线低使 START 等待超时 | 第 4、5 节；两根线是否空闲高 |
| FPGA 端有波形，芯片端没有 | 连线、连接器、串阻或焊接 | 同时/先后测串阻两侧 |
| AC 后第一个 ACK 就失败 | 芯片未正确收到地址或无法应答 | VDD、ADS、地址、SDA/SCL 方向及实际高低电平 |
| AC 有 ACK，3A 无 ACK | 寄存器地址字节/时序或链路异常 | 原始位序、SDA 数据稳定时间 |
| 写入三次 ACK 都有，读寻址失败 | 写路径可达，读事务/重复起始/AD 时序待查 | 展开读回事务，不先改触摸阈值 |
| 全部 ACK 有，但读回不是 5A | 读数据、采样或配置读回失败 | 比较实际总线数据和 FPGA 采样值 |
| 进入配置读回成功，后续停止 | 需要定位停止前的具体配置项 | 按第 7 节记录索引、寄存器、期望/实际值 |
| 最后 3A=00 写入并读回成功 | 初始化链路已有直接证据 | 转到键值和 INT 的交叉检查 |

不要把读回 `0xFF` 当作有效配置或“全部键按下”。它也可能来自未应答或 SDA 一直为高，需要结合地址 ACK 与数据波形判断。

若实测 ADS 确实接低，先确认是实物设计选择还是焊接错误。低电平对应 7 位地址 `0x57`，原始写/读字节为 `0xAE/0xAF`；现有主机把 `0xAC/0xAD` 写在 RTL 中，没有地址参数，不能只改解码器显示或注释就期待芯片应答。此时应先决定按原板接法修正 ADS，还是在后续诊断版本中匹配实际地址，并记录该变更。

### 6.3 波形异常时再做一次降速对照

先保存 100 kHz 的原始捕获。若怀疑边沿或采样，将诊断版本 I²C 改为 **25 kHz**，其他接线/寄存器/电源不变，由用户重新实现、下载后重复同一测试。25 kHz 是对照条件，不是宣布解决了硬件问题；当前发布参数仍是 100 kHz。

有示波器时，在芯片引脚侧看 SDA/SCL：记录低/高电平、上升时间和高低持续时间。100 kHz 标准模式可参照：SCL 低至少 4.7 μs、高至少 4.0 μs；START 保持至少 4.0 μs、重复 START 建立至少 4.7 μs；STOP 建立至少 4.0 μs，上升时间 30%～70% 不超过 1 μs。[NXP UM10204 Rev.7，第 44 页表 11](https://www.nxp.jp/docs/en/user-guide/UM10204.pdf)

上述时序用通用 I²C 测量方法；AiP5916 的直流识别还须达到前述 0.8/0.2 VDD 门限。10 kΩ 上拉、连线电容和探头都会影响边沿。如果降速改善，应进一步确认边沿和负载，不能直接写成芯片损坏或仅靠降速已全部修复。

## 7. T4：逐项核对初始化，确认最终已退出配置模式

当前程序索引从 0 开始，一共 25 项。每项都有一笔独立写和一笔独立读回；首次失败会停止后续操作。

| 索引 | 寄存器地址 | 期望写入及读回 | 检查目的 |
|---:|---|---|---|
| 0 | 3A | 5A | 进入配置模式 |
| 1 | 21 | 04 | 多键、INT 低有效电平模式、内部工作 1 MHz |
| 2 | 23 | 00 | 使能前 8 通道 |
| 3 | 24 | 00 | 使能后 8 通道 |
| 4 | 20 | 02 | 默认全局灵敏度 |
| 5～20 | 00～0F，逐地址独立操作 | 每项 04 | 每通道默认阈值 |
| 21 | 22 | 20 | 基线更新默认设置 |
| 22 | 2D | 00 | 正常开发模式配置 |
| 23 | 2A | 10 | 正常开发模式配置 |
| 24 | 3A | 00 | **退出配置，恢复触摸工作** |

每个失败只记录第一次：`索引 / 地址 / 写或读阶段 / ACK位置 / 期望值 / 总线实际值 / FPGA读回值`。不要在失败后仍记 `init_ok=1`；也不要只看写 ACK 就认定读回校验通过。

如希望先简化配置链路，可在后续诊断模式中先尝试“读默认寄存器、进入配置、只修改 MCON、退出配置、再次读取 MCON”的最短对照，再恢复全表；这属于待实现测试，不是当前程序已经在做。每次对照前重建相同上电条件，默认值只能用于真正复位/重新上电后的核对，不能要求已运行过的芯片仍保持出厂默认。

**通过条件：25 项逐项校验成功，最后 `SYSCON=0x00`，再开始评价触摸识别。** 此前不调整 GSR/KOR，也不打开特殊开发模式去掩盖通信失败。

## 8. T5：分开验证键值、INT 和 FPGA 输入

### 8.1 先读键值，不依赖 INT 决定是否读取

需要后续诊断程序或独立 3.3V I²C 主机支持，**现版本 MONITOR 状态没有这项读取**。使用外部主机时，先与 FPGA 的 SDA/SCL 断开，避免两个主机同时驱动。

分别用两次单字节事务读 `0x34`、`0x35`：

```text
keys16 = {KVR1(0x35), KVR0(0x34)}
```

1. 初始化成功后空手等待基线稳定，记录键值和 INT。
2. 按 C，保持约 1 秒，记录；松开约 1 秒，再记录。这里的等待是便于人工观察，不是芯片保证的扫描/建立时间。
3. 再试 G♯，分别验证低字节与高字节通道。
4. 即使 INT 高也定期读键值。读失败标记“无效”，不把失败替换为 `0000` 或 `FFFF`。

| 键值是否随触摸变化 | 芯片 INT23 是否变化 | FPGA 侧 U15 是否变化 | 优先结论与动作 |
|---|---|---|---|
| 是 | 是 | 是 | 芯片、键值与 INT 传输已有证据，查 `init_ok`、同步/滤波及 LED 输出 |
| 是 | 是 | 否 | INT 连线、J1-7、U15 约束/输入电平 |
| 是 | 否 | 否 | 查 MCON bit3、INT 输出和该支路硬件；键值变化已证明触摸识别在工作 |
| 否 | 是 | 是或否 | 先查读的是 34/35 而非 1C/1D、读事务/缓存、是否误读另一器件 |
| 否 | 否 | 否 | 初始化退出、芯片工作状态、参考电容和电极连接；仍不能只凭此判定芯片坏 |

若芯片侧和 FPGA 侧都能测到持续低，而灯不亮，先查是否已完成全部配置。不要跳过 `init_ok` 门控。

### 8.2 单独验证 U15 的输入链路

这是待补充的 `INT_INPUT_TEST` 模式：I²C 释放、忽略 `init_ok`，只同步 U15 并镜像到 LED。

- 必须先断开键盘 INT 与 U15 的连接，避免把触摸芯片的输出强拉到地。
- 依靠已确认的 3.3V 上拉观察高电平；再用约 10 kΩ 电阻将 **FPGA 输入侧** 拉向 GND，测量实际变低并观察 LED；释放后应恢复。
- 这个测试只证明 GPIO 输入/同步/LED 路径，不证明触摸芯片识别了按键。
- 当前正式测试不能直接套用此方法判断结果，因为它仍受 `init_ok` 门控。

### 8.3 如果通信正确但键值始终为零

依次检查：最后确实写回 3A=00 → KDR0/1 为 00 → SSOP24 的 C0 第 4 脚及 10 nF 到地 → 触摸通道串阻及电极连通 → 覆盖材料/电极触摸方式 → 电源和接地环境。不要把示波器探头长期接在触摸电极或 C0 上测试灵敏度，探头本身会改变电容负载。

这些条件确认后，再单独调整一个通道的 KOR，并保留默认值对照；KOR 越小越敏感、GSR 越大整体越敏感且扫描周期加长。`DMR0=08、DMR1=FF` 是特殊开发选项，本轮先不使用。

## 9. 建议补充的最小诊断程序规格（尚未实施）

如果没有逻辑分析仪，当前单灯方案无法区分多个失败原因。建议在**同一个测试工程**里增加参数选择的测试模式，保留现有基线和接线，不接入完整电子琴。

| 模式 | 要证明什么 | 必须能看到的信息 |
|---|---|---|
| LED_SELFTEST | 下载、灯号、时钟、K16 复位 | 强制亮灭、1 Hz 心跳 |
| INT_INPUT_TEST | U15 输入、同步和 LED | 原始/同步 INT，与初始化解耦 |
| I2C_PROBE | 芯片是否应答、能否正确读寄存器 | 总线空闲电平、地址 ACK、一次寄存器读结果 |

| 实体灯 | FPGA 管脚 | 诊断含义（建议，当前 CST 未加入其他灯） |

| LED1 | R26 | 主时钟心跳 |
| LED2 | L20 | 已获得地址 ACK |

| LED4 | N21 | 首次错误锁存，复位前保持 |

错误快照至少包括：`mode/stage、config_index、register_addr、write/read、ACK阶段、error_code、expected、actual、sda/scl回读、last_keys、keys_valid`。错误码应区分地址写 NACK、寄存器地址 NACK、数据 NACK、地址读 NACK、总线等待/事务超时和读回不一致，不只留一个 `error` 位。

首次失败快照不得被后续重试覆盖。若失败时芯片已进入配置模式，记录后可设计一次有界的“退出配置”清理尝试，并另存清理结果；不能因清理成功而把原初始化判为通过。错误展示可以先用 GAO 或 LED 编码，不新增未经分配的 UART 引脚。

## 10. T6：识别恢复后，再做逐键和组合验证

每键按住约 1 秒、松开约 1 秒，初筛各做 3 次，记录松开是否恢复 `0000`。先测单键，再测组合，不同时调整灵敏度。

全部为十六进制。单键时出现额外位，记录原值，排查通道映射或误触，不直接掩码隐藏。

组合序列：`C → C+E → C+E+G → C+G → G → 全松`，期望 `0001 → 0011 → 0091 → 0081 → 0080 → 0000`；过程中 INT 应保持低，最后全松才高。再测跨字节 `C+G♯=0101`，以及琴键+AUX。分字节读取不保证瞬间原子快照，因此先对保持稳定的组合比较，不把按/松瞬间一次不一致当作永久故障。

最终通过标准：单键按/松位序正确；持键时增减其他键不漏变化；全松键值归零且 INT 回高；多次复位后配置都完成。尚未测的项目填写“未测”，不能把 HDL 仿真或已有 STA 代替这些实物结果。

## 11. 快速分流表

| 首个明确现象 | 本轮先做什么 |
|---|---|
| 3.3V 或芯片 VDD 不正常 | 修供电/焊接，暂停触摸参数调整 |
| SDA/SCL 空闲被拉低 | 分离两端，查短路/上拉/驱动来源 |
| LED 强制测试也无效 | 下载、管脚、LED 实体编号 |
| 无任何 I²C 波形 | 时钟、K16、总线等待、抓取时机 |
| AC 无 ACK | 地址、ADS、电平、线序、供电 |
| 写有 ACK、读失败 | 重复 START、AD、读取采样 |
| 初始化在某项停止 | 保留第一错误，查该笔事务；确认是否滞留配置模式 |
| 已退出配置，KVR 变而 INT 不变 | MCON/INT 输出支路 |
| 芯片 INT 变、U15 不变 | INT 连线与 GPIO |
| U15 变、LED 不变 | init_ok、滤波及 LED 链路 |
| 通信和配置全过，KVR 始终为零 | C0、触摸通道/电极、覆盖层与基线，再做灵敏度对照 |
