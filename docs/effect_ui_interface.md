# 效果器参数与 UI 对接约定

## 页面与取值

| 控件 | UI 显示范围 | 音频值 | 默认值 |
|---|---|---|---|
| 效果选择 | 回声 / 房间混响 / 音量颤动 | mode = 0 / 1 / 2 | 0 |
| 效果开关 | 关闭 / 开启 | enable = 0 / 1 | 0 |
| 回声强度 | 0..100% | echo_wet = 0..256 | 64，25% |
| 混响强度 | 0..100% | room_wet = 0..256 | 64，25% |
| 音量颤动深度 | 0..100% | tremolo_depth = 0..256 | 128，50% |
| 音量颤动速度 | 1..10 Hz，整数步进 | tremolo_rate_hz = 1..10 | 5 Hz |

百分比转音频值用 `(百分比*256+50)/100` 的整数除法，先限幅到0..100。反向显示百分比用 `(音频值*100+128)/256`。强度表示原声与效果声的混合比例，不是总音量；100%表示全效果声，不保证主观音量与原声相同。颤动深度0表示无音量起伏，256表示可下探至零；调制峰值按8位三角波量化，可能略低于原声满增益。

UI 可先设计三个效果标签、统一开关，以及当前效果对应的参数区；切换效果应保留另外两种效果的参数。请保留原音色选择。建议提供恢复默认按钮，一次提交完整默认状态；当前 RTL 只有复位恢复默认，UI按钮由后续控制模块实现。

## synth_core 的实际接口

全部输入输出属于 `audio_clk` 域，在该主时钟上升沿操作，不用 frame_ce 当时钟。

| synth_core 端口 | 方向 | 含义 |
|---|---|---|
| effect_cfg_valid | 输入 | 参数整组有效；与ready同时为1的上升沿提交 |
| effect_cfg_ready | 输出 | 可提交；非复位时为1 |
| effect_echo_wet[8:0] | 输入 | 回声目标强度 |
| effect_room_wet[8:0] | 输入 | 混响目标强度 |
| effect_tremolo_depth[8:0] | 输入 | 音量颤动目标深度 |
| effect_tremolo_rate_hz[3:0] | 输入 | 音量颤动速度，整数 Hz |
| effect_cfg_applied | 输出 | 提交后的一个时钟周期确认，表示目标寄存器已接收 |
| effects_enable | 输入 | 既有效果开关电平，不包含在参数提交中 |
| effect_mode[1:0] | 输入 | 既有效果类型电平，不包含在参数提交中 |

示例：把四个参数保持稳定，将valid拉高一个audio_clk周期；在valid&&ready上升沿提交，再撤销valid。valid连续为1代表每个时钟都提交，并非仅响应上升沿。cfg_applied在连续提交时也可连续为1。复位时ready和applied为0，已接收的参数恢复默认。

四参数原子更新，未操作的参数也必须提交其当前目标值，不能填0代替。模块对强度/深度大于256的值限幅到256，速度0限到1、11..15限到10。生产连接必须驱动定义的0/1信号，不能依赖旧仿真中未接端口的Z值。

`audio_effects` 对应端口名为 cfg_valid、cfg_ready、cfg_applied、cfg_echo_wet、cfg_room_wet、cfg_tremolo_depth、cfg_tremolo_rate_hz。模式/开关沿用 mode、enable。

## 生效时间与显示状态

提交确认表示目标已保存，不表示实际音频强度已经到达目标。三种强度/深度每接收一个48kHz样本向目标移动1，总跨度最多256采样，约5.33ms。只在接收样本时前进，输入停止时不会假装完成渐变。每个处理中的样本锁存自己的参数；同一时钟既接收样本又提交配置时，该样本使用提交前的状态，之后样本开始跟随新目标。

速度更新不清零低频振荡器相位，之后样本采用新相位增量；不对速度另做线性扫频。旁路时仍更新各参数和效果历史。已有开关渐变和先回原声再换效果的逻辑保留，处理延迟仍为接收后第3个后续时钟沿输出，每样本占用4个主时钟。

当前 RTL 没有新增目标读回总线。未来控制器应在audio域维护权威目标快照，并在确认后把该快照传回UI；UI显示目标设置而非内部每采样变化的平滑值。S3改变模式或开关时也必须通知UI，避免显示与声音不同步。

## 两边合并时需要补齐的连接

1. 屏幕驱动、GT911触摸、物理引脚与现有时序先沿用周建涛分支，不猜接线；触摸目前默认关闭，UI画出来不等于触摸已可用。
2. 在audio域增加统一控制状态，协调S3与UI操作。S3当前自行维护模式/开关；不能把UI输出和按钮输出直接并接，也不能在每帧用旧按钮状态覆盖UI设置。同拍冲突需明确优先级，建议UI完整命令优先，并让按钮继续基于最新统一状态执行。
3. 如果UI控制发生在pixel_clk或其他时钟域，用保持数据的请求/确认邮箱或异步FIFO传递完整快照；禁止每位独立双触发器同步多位参数。源数据在请求前稳定，保持到确认；握手状态同步并考虑两个时钟域复位/重启。当前参数接口本身不提供CDC。
4. 建议跨域快照共34位：bit33开关、32:31模式、30:22回声强度、21:13混响强度、12:4颤动深度、3:0颤动速度。此打包是合并约定，当前没有名为该总线的硬件端口。接收后在audio域同时更新模式、开关并向四参数接口发一拍valid。
5. 显示状态返回也须原子跨域。返回的是audio域实际接受的设置，不能只显示触摸本地缓存。参数渐变过程无需每采样跨域。
6. 主工程 keyboard_top 暂时把effect_cfg_valid固定为0，不新增外部管脚；默认值与旧试听版本一致。杨同学应在显示分支做UI并保留对接位置，后续由整合分支接通并验证。

本轮未实现回声时间可调、混响衰减可调、合唱或效果叠加。界面先按本文件四参数实现，不要把暂未支持的滑块标成已可用。
