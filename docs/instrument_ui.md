# 电子乐器 UI 与矩阵菜单

## 当前版本与分支关系

2026年10月23日，工作分支为 `feature/instrument-ui`。在独立分支整合音频参数版本 `b35cf2c` 与周建涛显示/触摸版本 `dd49c83`，再增加可操作的UI。main、feature/audio-effects、codex/fpga-migration本身不被覆盖；本版尚待重新综合、布局布线、检查时序与实板验证。此前三效果版的试听成功不等于新显示整合版已经验收。

显示沿用周同学已试亮的800×480、独立35MHz像素PLL、RGB666引脚、DE-only扫描及PCLK相位。原音频PLL、音色/32声部/曲谱/功放及效果算法保持。新界面使用一个共享5×7字库和两级像素寄存器，RGB、DE、HS、VS一致延迟；不是屏幕截图播放器，不使用CPU或整帧显存。

## 屏幕内容

上方显示演奏/参数控制状态。三种音色、三种效果各自保留选择高亮，FX开关另外显示，选择效果会自动开启。左参数卡根据当前效果显示回声/混响强度或音量颤动深度；右卡仅在颤动模式下提供速度加减，其余显示固定150ms回声时间或SMALL ROOM模型。底部显示实际声部数、音频就绪、自动曲谱/现场演奏、鬼键/错误和触摸状态。

模式按钮152×56像素，音色按钮176×60，效果按钮240×60，参数加减64×56，按钮间有空隙。标签使用英文像素字以避免未经提供的中文字库依赖。触摸命中框与渲染采用同一份 `src/config/ui_layout.svh`，空隙和无效参数区域不触发动作。

`reports/instrument_ui/2026-10-23/ui_0.png` 至 `ui_3.png` 是实际RTL光栅输出的仿真预览，包含演奏、混响菜单、颤动菜单及错误状态。它们不是实屏照片，预览中的声部数、触摸状态是测试输入。

## 板载按钮

| 操作 | 功能 |
|---|---|
| S0 短按后松开 | 选择正弦音色 |
| S0 按住约0.8秒 | 切换演奏/菜单；持续按住只执行一次，长按不改变音色 |
| S1 按下 | 选择笛管类音色 |
| S2 按下 | 选择簧管类音色 |
| S3 短按后松开 | 开关当前效果 |
| S3 按住约0.8秒 | 回声→房间混响→音量颤动→回声，并开启；持续按住只切一次 |
| USR复位 | 恢复默认效果参数和演奏模式，并重播小星星 |

与旧音频版相比，S0选择正弦改为松开时生效，以便区分菜单长按。S0/S1/S2/S3的原有K16/F15/G15/G16引脚不变。按钮和矩阵/触摸共用一个audio_clk域控制状态，S3始终从最新选择继续循环。板载按钮事件优先于同拍UI动作；同拍矩阵命令优先于触摸命令。

## 矩阵键盘菜单

R1为物理最上行，C1为最左列；不用键帽印字判断编号。在演奏模式下仍正常发声；先长按S0进入菜单，再按下表操作。

| 行 | C1 | C2 | C3 | C4 |
|---|---|---|---|---|
| R1 | 正弦 | 笛管 | 簧管 | 返回演奏 |
| R2 | 回声 | 混响 | 音量颤动 | 效果开关 |
| R3 | 当前强度/深度减5% | 当前强度/深度加5% | 颤动速度减1Hz | 颤动速度加1Hz |
| R4 | 效果恢复默认 | 保留 | 保留 | 返回演奏 |

每次须松开所有矩阵键后再操作下一键；长按不自动重复。速度加减仅对颤动有效。三种效果各自保留参数，切换效果不会把其他效果参数清零。默认回声25%、混响25%、颤动深度50%、速度5Hz；恢复默认会选择回声并关闭效果，不改变音色和菜单状态，也不重播曲谱。

进入菜单时，键盘输入向音符适配器呈现全松键，继续发送必要的Note Off，等待原ADSR尾音自然消退；不冻结音符状态。退出菜单后，返回演奏的按键即使还按住也不会发声，必须全部松开后再按。矩阵扫描持续运行，鬼键仍遵循原保护策略。释放资格时间覆盖一轮完整去抖周期，防止鬼键清零的短暂状态被误认为已松开。

自动小星星可继续播放，菜单不会中断曲谱。可以在演奏期间调整效果；曲谱结束后若仍处菜单，键盘继续保持菜单用途。菜单不会额外触发音符，也不保证无二极管矩阵任意多键无冲突。

## 参数与跨时钟传递

所有输入先变成audio_clk域UI动作，由timbre_control统一维护音色、模式、效果、参数。百分比用0..100、5%步进保存，经常量查表转换为0..256整数，映射为四舍五入后的p×256÷100。四参数以valid/ready完整提交到synth_core，阻塞时保持已提交元组稳定，后续目标可合并为最新值；确认后显示目标设置，效果器按原逻辑逐采样平滑变化。改变速度不清零低频振荡器相位。

显示由一个64位音频域状态快照经四相握手送入像素域，并仅在帧边界发布，包含实际音色、效果、参数和声部计数。显示不另存一份独立的按钮状态，不会因S3操作而停留在旧效果名称。音频不等待显示确认。

触摸启动后，其71位原始状态/分辨率快照先从50MHz参考域原子传入音频域，再生成一次触摸动作；不逐位同步多位参数。两个相关域复位或失锁时同时重置握手，释放由各域同步。

## 触摸状态与保留范围

生产顶层现默认 `TOUCH_ENABLE=1` 和 `TOUCH_UI_ENABLE=1`。周同学的GT9110及I2C驱动、AB26/U25/V23/R23映射不改；SCL/SDA/INT/RST按开漏复位与I²C流程工作。默认启动只表示RTL会访问器件，并不代表此前显示 `TOUCH ERROR` 的实板供电、上拉或通信问题已经修复。

只有ready且无错误、设备报告原始分辨率800×480、单点且坐标在范围内时才允许触摸控制；没有猜测坐标缩放或旋转。复位、错误或启用时若手指已按住，须先抬起；每次按下只触发一次，不做拖动或长按连发。

底部TOUCH OFF表示驱动关闭，WAIT表示未就绪，ERROR表示协议错误；MONITOR表示只监测或分辨率尚未符合控制条件；READY才表示已允许坐标操作。即使仿真中命中框通过，也仍需实物核对排线方向、电压、坐标方向和触摸模块工作状态。

## 上板检查

1. 更新main后关闭旧工程，打开根目录keyboard_adsr.gprj，顶层keyboard_top；确认工程依赖和CST来自本次合并版本。
2. 保留矩阵键盘、MAX98357A和周同学杜邦线。先断电，再按此前已确认方向接回显示排线；触摸会在复位释放后自动启动。
3. 自行执行Gowin综合、布局布线，检查61.44MHz音频域、35MHz像素域、Setup/Hold及资源/RAM推断。SDC沿用LCD_ENABLE=1对应的平面命令；若自行关闭LCD，需按原说明处理三条像素约束。
4. 核对Programmer的.fs来自本次工程impl/pnr，以SRAM方式试听。默认程序先播放小星星，随后恢复键盘；菜单在曲谱期间也应可打开。
5. 长按S0进菜单，按R2C2选混响，R3C2加大强度，检查屏幕数值、进度条与声音变化；切颤动后验证深度与速度。菜单按键本身不能弹出新音。
6. 按R4C4退出并继续按住，耳机应不发出该键的音；全部松开后再弹奏。持音进入菜单后应正常释放；核对S0长按不改变音色、S3循环与屏幕同步。
7. 按R4C1恢复默认，检查25%/25%/50%/5Hz和FX关闭。观察屏幕边缘、文字、色彩及是否有新增噪声。
