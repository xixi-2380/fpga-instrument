## 一、进入、退出与页面布局

长按板载 S0 约 0.8 秒进入设置，再触摸 `PCB`。系统先平滑静音，确认静音后才显示专项页。页面内不发出演奏声音；点击 `BACK` 返回，等待屏幕实际离开专项页后平滑恢复当前音量。

PCB 页没有改动 S0/S1/S2/S3 和复位按钮的原有作用，旋钮也仍控制效果。旋钮不负责选择 PCB、翻页或调整 GSR/KOR。

页面大致分为五区：

```text
PCB DEBUG / MUTED          BUILD 26102801            BACK

OVERVIEW     SENSE          BUS          KEYS         EC11

PCB -   PCB +   CH -   CH +   GSR/KOR   VIEW 0   FREEZE

PCB CH TAB PAGE  : ........
以下七行随子页和 VIEW 变化
……

APPLY    DEFAULT    REINIT    ALL KOR    CLEAR    -    +
```

`BUILD 26102801` 是源码中的固定显示标识，不是每次编译自动变化的编号，不能单凭它判断是否已经使用 W23 接线的新位流；应同时核对实际编译来源和文件哈希。

## 二、所有按钮的作用

| 按钮 | 作用与注意事项 |
|---|---|
| `BACK` | 退出专项页，返回设置；需要演奏时再退出设置 |
| `OVERVIEW` | 总览：在线、有效、配置、故障和计数 |
| `SENSE` | 灵敏度编辑、应用与回读 |
| `BUS` | I²C 输入/驱动、事务阶段、错误和历史 |
| `KEYS` | 原始读取、候选/稳定键值、发音资格及音符链路 |
| `EC11` | 旋钮状态、动作计数、目标参数及效果握手 |
| `PCB - / PCB +` | 在1～3板之间循环选择；EC11 页对应1～3号旋钮 |
| `CH - / CH +` | 在通道 00～0F 之间循环选择；00～0B 为琴键，0C～0F 为 AUX |
| `GSR / KOR` | 切换当前编辑项；按钮文字表示当前选中项 |
| `VIEW` | 详情编号按 0→1→2→3→0 循环，各子页含义不同，见下表 |
| `FREEZE` | 冻结当前诊断文字，按钮变为 `LIVE`；采集、计数和故障处理仍继续 |
| `LIVE` | 恢复刷新，显示采集到的新状态 |
| `APPLY` | 把选中板的整套编辑值提交给键盘，成功后才更新 APPLIED |
| `DEFAULT` | 仅把选中板的编辑值恢复为 GSR=02、全部 KOR=04；仍需 APPLY |
| `REINIT` | 使用选中板最后成功配置重新初始化；尚无成功配置时使用默认备用值 |
| `ALL KOR` | 将当前通道的编辑 KOR 复制到本板16个通道；仍需 APPLY |
| `CLEAR` | 清选中板的键盘统计/总线历史、对应旋钮计数及关联历史；不改灵敏度、不擦 Flash |
| `- / +` | 仅在 SENSE 页修改选中编辑项，每次减/加1，达到边界后停止 |

`APPLY / REINIT / DEFAULT / ALL KOR` 不要求一定处在 SENSE 子页才会响应；为避免误操作，建议只在 SENSE 中使用它们。配置等待期间不能再次应用，也不能修改编辑值。

除 `FREEZE/LIVE` 和 `CLEAR` 外，页面操作通常会解除冻结。冻结时点击 CLEAR，显示仍可能保留旧数字，点击 LIVE 后再确认清零结果。发生新事件时计数可立即再次增加。

### VIEW 对照表

| 子页 | VIEW 0 | VIEW 1 | VIEW 2 | VIEW 3 |
|---|---|---|---|---|
| OVERVIEW | 总览 | 同总览 | 同总览 | 同总览 |
| SENSE | 单通道和应用结果 | 16通道编辑 KOR | 16通道成功配置 KOR | 16通道已验证回读 KOR |
| BUS | 总线现场 | 最新4条总线事件 | 较早4条总线事件 | 同 VIEW 0 |
| KEYS | 选中板12键资格/路由 | 全36键资格及标志 | 同 VIEW 1 | 同 VIEW 1 |
| EC11 | 旋钮现场和计数 | 最新4条关联事件 | 较早4条关联事件 | 同 VIEW 2 |

切换顶部子页会把 VIEW 重置为0。切换板号不会自动把通道归零。

## 三、先学会读八位十六进制数

页面每行末尾显示一个32位字，例如 `00000204`。最右侧是低位 bit0，最左侧是高位 bit31；每个十六进制数字占4位，每两位为一个字节。

| 十六进制 | 十进制 |
|---|---|
| 04 / 08 | 4 / 8 |
| 0A / 0F | 10 / 15 |
| 10 / 32 / 64 | 16 / 50 / 100 |
| FF / FFFF | 255 / 65535 |

不同字段的字节顺序不同，**不能按英文标签顺序猜左右顺序**。后面的表格以实际拼接为准。

### 公共首行：PCB CH TAB PAGE

四个字节从左到右依次为：板号、通道、子页、VIEW。

```text
02030100 → PCB2、通道03、SENSE子页、VIEW 0
```

子页编号：`00=OVERVIEW`、`01=SENSE`、`02=BUS`、`03=KEYS`、`04=EC11`。板号显示01～03，通道显示00～0F。

## 四、OVERVIEW：先判断板子是否正常

### 1. ONLINE VALID MUT

这是组合状态位图，低10位有效：

| 位 | 为1的含义 |
|---|---|
| bit0 | 显示冻结 |
| bit1 | 有一项 PCB 配置请求正在等待 |
| bit2 / 3 / 4 | PCB1 / PCB2 / PCB3 通信在线 |
| bit5 / 6 / 7 | PCB1 / PCB2 / PCB3 按键数据有效 |
| bit8 | 最终音频静音已确认 |
| bit9 | 硬件诊断跨时钟域快照已可用 |
| bit31..10 | 保留，通常为0 |

三板在线、三板数据有效、静音和诊断有效，且未冻结、无等待时，通常显示 `000003FC`。冻结后最低位变为1，例为 `000003FD`。

通信在线与数据有效是两项独立状态。某板可以保持在线，但因50ms内没有一致快照而失去按键发音资格。bit9 也只说明诊断通道已有快照，不代表三块键盘都正常。

### 2. STATE CFG FAIL I

低16位是**选中板**的状态：

| 位 | 含义 |
|---|---|
| bit0 | 同步后的 INT 电平；显示电平，不是中断次数 |
| bit2..1 | 当前双遍读取字节索引，0～3 |
| bit7..3 | 配置步骤索引，0～24，显示值为十六进制 |
| bit9..8 | 连续通信失败轮数，通常0～2，第三次触发重初始化 |
| bit10 | 当前通信/配置故障标志 |
| bit11 | 通信在线 |
| bit12 | 按键数据有效 |
| bit13 | 正在应用页面提交的配置 |
| bit14 | 当前初始化/配置已完成 |
| bit15、bit31..16 | 保留 |

正常运行重点看 bit14、bit12、bit11 为1，bit10为0。低位的读字节索引和 INT 会随运行变化，不必要求整个字固定为某个值。

配置索引顺序：0进入配置；1～3为固定初始化项；4写 GSR；5～20写通道00～0F的 KOR；21～23为固定配置项；24退出配置。索引卡在某处时，结合 BUS 和最后故障字判断。

### 3. LAST ERROR BYTES

从左到右四个字节：

```text
原因码 | 寄存器地址 | 期望字节 | 实际字节
```

例如 `23072829`：原因23，寄存器07，期望28，实际29。

| 原因码（HEX） | 含义与判断 |
|---|---|
| 00 | 没有保留的故障 |
| 11 | 轮询按键时发生 I²C NACK |
| 12 | 轮询按键时发生总线/时钟超时 |
| 14 | 50ms内没有一致按键快照，数据过期 |
| 21 | 初始化/应用配置时写事务失败 |
| 22 | 初始化/应用配置时读事务失败 |
| 23 | 配置回读与期望值不符 |
| 2F | 读键盘状态机发生非法状态并进入恢复 |

配置写/读失败的底层原因仍需结合 NACK/TIMEOUT 计数和 I²C 错误码判断。通信错误或数据过期时，期望/实际字节可能为00；不能把这两个00解释为芯片实读结果。

这是**最后一次故障的记录**，自动恢复后不会立即消失。当前是否仍故障，应看状态位、在线、数据有效和计数是否继续增加。健康且数据有效时，CLEAR 可以清除历史故障字；仍有故障时不会清除它。

原因13表示“双遍读值变化”，仅记在总线历史和变化计数中，不作为故障覆盖此行。

### 4. 统计与时间

| 字段 | 左四位（高16位） | 右四位（低16位） |
|---|---|---|
| GOOD CHANGED HEX | 双遍读值变化次数 | 一致快照次数 |
| NACK TIMEOUT HEX | 超时次数 | NACK次数 |
| REINIT STALE HEX | 数据过期次数 | 重初始化次数 |

例如 `NACK TIMEOUT HEX : 00020005` 表示2次超时、5次 NACK。上述计数到 FFFF 后饱和，不会回绕。NACK/超时统计同时覆盖配置和按键轮询。

`LAST GOOD MS HEX` 是最近一次一致快照的毫秒时间，使用十六进制，时间基准从系统复位开始。它不是“经过的时间”，应配合 BUS 页的 AGE 观察。

## 五、SENSE：灵敏度编辑、应用和回读

### 1. 参数方向

| 参数 | 范围（HEX） | 默认 | 增大后的效果 |
|---|---|---|---|
| GSR | 00～0F | 02 | 整板更敏感，扫描周期也会变化 |
| KOR | 01～FF | 04 | 当前通道更不敏感 |

建议先保持 GSR=02，逐通道调整 KOR。琴键误触时逐步增大 KOR；不灵敏时先排除通信、初始化和菜单屏蔽，再逐步减小 KOR。

### 2. VIEW 0 各行

| 字段 | 说明 |
|---|---|
| DRAFT GSR / KOR | 选中板的编辑 GSR、选中通道的编辑 KOR，尚未应用 |
| APPLIED GSR KOR | 最后一次整板全部成功应用的对应参数 |
| READBACK GSR KOR | 当前已有验证资格的实际回读值 |
| PENDING / RESULT | 配置等待标志和选中板最近一次页面配置结果 |
| LAST ERROR BYTES | 与总览相同的最后故障字 |
| GSR+ SENSITIVE | 当前编辑 GSR，并提示增大会更敏感 |
| KOR+ LESS SENSE | 当前通道编辑 KOR，并提示增大会更不敏感 |

前三行的格式为 `00000GKK`，G为一位 GSR，KK为两位 KOR。例如 `00000208` 表示 GSR=02、KOR=08。

`PENDING / RESULT`：bit8为等待标志，低8位为结果码，其余为0。

| 示例 | 含义 |
|---|---|
| 00000100 | 有请求在等待 |
| 00000000 | 当前无等待，且未保留错误；也可能还没有提交过页面配置 |
| 00000023 | 本板最近一次页面配置回读不符 |
| 00000031 | 配置请求等待就绪或完成超时，当前默认总预算约3秒 |

等待标志是全局的，结果码按板保存。等待时切换板号，看到的结果码可能属于新选板此前的请求。因此建议应用期间保持板号不变，回到 VIEW 0 核对结果。

**不能只凭00000000认定本次应用成功。** 应确认确实提交过请求、等待已结束，并且 APPLIED 和 READBACK 已变为期望的新值。

### 3. VIEW 1～3 的16通道分组

VIEW 1的行名为 `DRAFT CH GROUP`，显示编辑 KOR；VIEW 2为 `APPLIED CH GROUP`，显示成功配置 KOR；VIEW 3为 `READBACK CH GRP`，显示已验证的回读 KOR。第一至第四组的数据顺序如下：

| 组（从上向下） | 从左到右的通道 |
|---|---|
| 第1组 | 03、02、01、00 |
| 第2组 | 07、06、05、04 |
| 第3组 | 0B、0A、09、08 |
| 第4组 | 0F、0E、0D、0C |

每通道占两位。例如第一组 `08060402` 表示 CH03=08、CH02=06、CH01=04、CH00=02。不要把最左字节当成 CH00。

分组页的第1～4行替换了原来的单通道/等待结果显示；要看 PENDING 和结果，请回 VIEW 0。分组页只列 KOR，GSR 可回 VIEW 0 查看。

`NO APPLIED CFG : FFFFFFFF` 表示该板从未完成一次整板成功配置，备用默认值不能冒充成功结果。曾经成功后断线，APPLIED 仍可以保留，表示“最后成功值”，不表示现在在线。

`UNVERIFIED READ : FFFFFFFF` 表示所需回读尚未全部验证。分组内只要有一个通道未验证，就把整组显示为未知；它不表示芯片真的返回了四个FF。单通道页还会要求 GSR 也已验证。

### 4. 一次完整调整

1. 选择 PCB 和 CH，回到 SENSE / VIEW 0。
2. 选 GSR 或 KOR，用 -/+ 小幅调整，先核对 DRAFT。
3. 需要统一全板 KOR 时点 ALL KOR；它会同时影响4个 AUX通道的编辑值。
4. 手离开电极，点 APPLY，等待完成。
5. 核对结果、APPLIED、READBACK；失败时保留最后故障字。
6. BACK 返回，并退出设置，松开重按琴键试听。

应用流程为：等待当前事务结束→暂停目标板发音资格→进入配置→逐项写入和回读→退出配置→全部成功才提交 APPLIED。失败后自动恢复最后成功配置。其他板继续采集。

DEFAULT 只恢复编辑值，REINIT 使用最后成功值，二者不是同一操作。所有灵敏度参数仅保存在运行期间，断线重连保留；系统复位或断电恢复默认，不写入 Flash。

## 六、BUS：总线现场与事件历史

### 1. VIEW 0 / 3：I2C STATE / PINS

本行是底层64位总线诊断的低32位：

| 位 | 含义 |
|---|---|
| bit0 | 事务错误标志；新事务启动时清除，可能保留上次事务错误 |
| bit1 | 总线控制器忙 |
| bit2 | SDA主动拉低，1=拉低，0=释放 |
| bit3 | SCL主动拉低，1=拉低，0=释放 |
| bit4 | 同步采样的 SDA 实际数字电平 |
| bit5 | 同步采样的 SCL 实际数字电平 |
| bit6 | 重复起始标志 |
| bit7 | 当前/最近事务为读操作 |
| bit10..8 | 当前位索引，0～7 |
| bit13..11 | 事务阶段 stage，见下表 |
| bit18..14 | I²C 状态机编号，见后表 |
| bit26..19 | 接收字节寄存器 RX，移入过程中可能尚不完整 |
| bit31..27 | 发送字节 TX 的低5位 |

开漏“释放”不等于线一定为高：bit2=0而bit4=0，表示本控制器没有拉低 SDA，但线被外部拉低，或尚未上升；SCL同理。页面采样不能测出模拟电压或上升时间。

### 2. I2C ERR ADR TXRX

本行是同一64位诊断的高32位，字段在本行内的位置如下：

| 位 | 含义 |
|---|---|
| bit2..0 | TX 的高3位，即 TX[7:5] |
| bit10..3 | 当前事务寄存器地址的低8位 |
| bit18..11 | 底层超时计数器的低8位 |
| bit26..19 | I²C 错误码：00=无、01=NACK、02=超时/中止 |
| bit31..27 | 保留 |

超时计数仅显示低8位，既不是毫秒值，也不能用于还原完整超时时长。TX/RX字段也不表示每个字节都有单独保存的 ACK 结果；ACK需结合阶段、错误和回读判断。

### 3. 事务阶段与状态机

| stage | 含义 |
|---|---|
| 0 | 发送设备地址＋写方向 |
| 1 | 发送寄存器地址高字节；当前键盘单字节地址模式通常不用 |
| 2 | 发送寄存器地址低字节 |
| 3 | 重复起始后发送设备地址＋读方向 |
| 4 | 发送写数据字节 |

以下编号为十进制；从屏幕提取出的值仍是十六进制：

| 状态编号 | 名称 | 含义 |
|---|---|---|
| 0 | IDLE | 空闲 |
| 1 | FREE | 等待总线空闲 |
| 2 | START_HOLD | 起始保持 |
| 3 / 4 / 5 | TX_LOW / TX_RISE / TX_HIGH | 发位：低相位 / 等待SCL变高 / 高相位 |
| 6 / 7 / 8 | ACK_LOW / ACK_RISE / ACK_HIGH | 接收从机ACK的三个相位 |
| 9 / 10 / 11 | RX_LOW / RX_RISE / RX_HIGH | 接收数据的三个相位 |
| 12 / 13 / 14 | MACK_LOW / MACK_RISE / MACK_HIGH | 主机给读数据应答的三个相位 |
| 15 / 16 / 17 | RE_LOW / RE_RISE / RE_HIGH | 重复起始的三个相位 |
| 18 / 19 / 20 / 21 | STOP_LOW / STOP_RISE / STOP_HIGH / STOP_FREE | 停止及释放总线 |

例如状态0A是十进制10，对应 RX_RISE。等待SCL升高期间持续低电平，最终可能触发超时。

### 4. 其余行与 VIEW 1 / 2

`INIT / BYTE /INT` 与 OVERVIEW 的状态字相同。`LAST ERROR BYTES`、`NACK TIMEOUT HEX`、`LAST GOOD MS HEX` 也与总览一致。

`AGE MS HEX` = 当前毫秒时间 − 最近一致快照时间。例如 `00000032` 为50ms。它表示快照年龄，不是单次 I²C 事务耗时；在尚无成功快照时应先结合初始化状态判断。

VIEW 1 / 2 的事件行名为 `BUS EVENT LOG`。VIEW 1 的上四行显示最新4条总线事件，VIEW 2显示再早4条，共保留最近8条，最新一条在上面。下三行仍是计数和时间。

```text
事件字格式：TTTT RR AA
TTTT = 毫秒时间低16位
RR   = 原因码
AA   = 当时事务寄存器地址低8位
```

原因包含11、12、13、14、21、22、23、2F。13表示两遍读值不同，它属于数据变化，不会单独触发通信掉线。历史的地址是记录事件时的事务地址，不能替代 LAST ERROR BYTES 中专门保留的故障地址。

时间低16位约每65.536秒回绕，不能用大小排序推断跨回绕前后的先后；按屏幕行的先后顺序读。全0也可能是尚未填充的历史项。

底层总线现场约每1ms采集，页面约100ms刷新，不能用它逐边沿观察 I²C；短错误依靠累计计数和历史定位。

## 七、KEYS：按键从读取到发音的链路

实际链路为：两遍读取→一致快照→逐键确认→数据有效→松键重武装→菜单/播放屏蔽→音符握手→物理声部→PCM输出。页面显示其中的选定状态，并不是每拍完整波形记录。

### 1. RAW PAIR1 PAIR2

**左四位是第二遍，右四位是第一遍。** 每遍为16通道位图，bit0对应CH00，bit15对应CH0F。

例如 `00010001` 表示两遍最近保存值都是0001，即CH00为1。`00000001` 表示第二遍0000、第一遍0001。

这两个寄存器在读取过程中分阶段更新，显示快照可能落在中间，甚至包含不同阶段保存的字节；屏幕上看到一次不相等，不等于刚完成的一轮必定失败。应结合 GOOD/CHANGED 计数、候选/稳定值和数据有效状态判断。

这里是芯片报告的按键位图，不是“原始电容值”。

### 2. STABLE CANDIDATE

**左四位是候选值，右四位是稳定值。** 与英文标签左右顺序不同。

例如 `00010000` 表示CH00已经进入候选，但稳定值尚未按下；后续连续一致后可能成为 `00010001`。

每个按键的按下与松开都需要连续两次一致快照确认。双读变化会单独计数并最多追加两次重试；NACK/超时按连续三轮失败处理，释放该板并重初始化。数据50ms不一致而过期时，在线状态可以保持，但发音资格停止。

### 3. VIEW 0：ARM / ROUTE PCB

格式为 `0AAA0RRR`：AAA为选中板12个琴键的重武装位图，RRR为经过屏蔽后的实际路由位图。

| 位图 | 为1的含义 |
|---|---|
| ARM | 该键已经满足“先松开再按”的重新准入资格，不代表正在按下 |
| ROUTE | 该键此刻被作为手动琴键状态送往音符事件生成器，不代表音源已经接受 |

12位中bit0为本板CH00，bit11为CH0B，不包括 AUX。例如 `0FFF0000` 表示12键都有资格，但当前没有键被路由。

**PCB DEBUG 位于设置菜单内，菜单会屏蔽手动琴键，并清除重武装资格，因此 ARM 和 ROUTE 通常都为0。** 这不是按键读取失败的证据。可以在页内看原始/稳定位图，退出菜单后松开重按再试听；当前页面没有在演奏时录制并回放完整手动链路的功能。

### 4. BLOCK EVENT FLAG

本行拼接了多种状态：

| 位 | 含义 |
|---|---|
| bit3..0 | 全部36键路由位图的最高4键，即PCB3的CH08～CH0B |
| bit4 | note_valid，当前有待交付音符事件 |
| bit5 | note_on，当前事件是按下；0表示释放，需与valid结合 |
| bit6 | note_ready，音源准备接收 |
| bit7 | 蓝牙路径当前占用音符接口 take_bt |
| bit8 | 本地曲谱路径占用 local_score_busy |
| bit9 | 菜单屏蔽 menu_mode |
| bit10 | 实际效果配置请求，包括蓝牙软复位后的恢复请求 |
| bit11 | 效果配置可接受 cfg_ready |
| bit12 | 效果配置已应用 cfg_applied |
| bit13 | 显示用音频样本有效脉冲 visual_sample_valid |
| bit14 | 输出欠载 underrun 标志 |
| bit15 | 音频启动准备就绪 input_ready |
| bit18..16 | 三效果开关掩码，bit16回声、bit17混响、bit18颤音 |
| bit19 | 回声编辑强度模式，0为编辑时间 |
| bit20 | 颤音编辑速度模式，0为编辑深度 |
| bit27..21 | 回声强度百分比 |
| bit31..28 | 混响百分比的低4位，不能当成完整混响值 |

短 valid/ready/applied 脉冲可能在100ms刷新之间经过，屏幕上没看到1不代表没发生。请结合音符计数和 EC11 页的效果握手累计计数。underrun由输出缓冲保留，CLEAR不会清它；它也可能被音频复位/输出清除路径清除，不应只看其某一帧推断全部历史。

### 5. VIEW 1 / 2 / 3：全部重武装位图

`ARMED KEYS LOW` 显示全部36键资格的低32位：bit0～11对应PCB1，bit12～23对应PCB2，bit24～31对应PCB3前8键。

`ARMED HI / FLAGS` 的bit31..28为最后4键资格（PCB3 CH08～0B）；低28位沿用上表 BLOCK EVENT FLAG 的bit27..0。此处最左四位已经换成资格信息，不能再解读为混响百分比。

### 6. 其余三行

| 字段 | 含义 |
|---|---|
| NOTE FCW | 当前音符接口的32位频率控制字；不是音符编号，仅在事件有效时具有对应含义 |
| HELD VOICES | 32个物理声部的持有位图；bit0～31对应物理槽位，不对应固定琴键或PCB |
| NOTE / PCM COUNT | 左四位为全局已握手音符事件数，含按下和释放；右四位为全局显示音频样本有效次数 |

音符计数不是“按键次数”。PCM计数也不是“非零声音次数”，静音时仍会增加。两者均到FFFF饱和，CLEAR不清除；按48kHz连续输出时，PCM计数约1.37秒即可饱和。音符可能来自后台蓝牙/曲谱，不能把全局计数都归因于选中PCB。

HELD为0不表示所有松键尾音都已消失；当前行没有显示32声部的完整ACTIVE位图。页面也未直接列出最终左右PCM数值或每个I²S串行字。

## 八、EC11：旋钮输入、点击与效果交付

PCB选择1/2/3时，本页对应旋钮1/2/3；CH选择不改变旋钮。当前接线为：

| 旋钮 | A | B | SW | 控制 |
|---|---|---|---|---|
| 1 | V16 | Y21 | V17 | 回声时间/强度 |
| 2 | U16 | U15 | W21 | 混响强度 |
| 3 | T23 | R25 | **W23** | 颤音深度/速度 |

### 1. RAW SYNC AB SW

这是选中旋钮诊断的低32位：

| 位 | 含义 |
|---|---|
| bit0 / 1 / 2 / 3 | 双击 / 单击 / 向下 / 向上的事件脉冲 |
| bit5..4 | 上次解码的 AB，bit5=A、bit4=B |
| bit7..6 | 滤波后的稳定 AB，bit7=A、bit6=B |
| bit8 / 9 / 10 | 同步后的 SW / B / A |
| bit11 / 12 / 13 | 原始 SW / B / A 数字输入 |
| bit15..14 | 保留 |
| bit16 | 按钮去抖后的电平，1=松开，0=按下 |
| bit17 | 本次按住期间发生过旋转 |
| bit19..18 | 点击状态，见下表 |
| bit23..20 | 尚未凑满一格的有符号四位步数；例如F表示−1 |
| bit31..24 | 单击等待计时低8位，单位ms |

点击状态：0=空闲；1=第一次按下；2=第一次释放后等待双击；3=第二次按下。单击通常在约250ms双击窗口结束后才产生；按住约600ms或按住转动后松开，不产生单击/双击。

AB每格默认按4个有效相位变化解码。遇到非法跳变会丢弃未完成的部分步数，所以转动时不是每个电平变化都增加一次完整步数。增加/减少是软件解码方向，需结合实际旋钮方向核对。

### 2. 动作计数行

| 字段 | 左四位（高16位） | 右四位（低16位） |
|---|---|---|
| HOLD CLICK UP | 向上完整步数 | 按住时间，单位ms，当前默认最多600 |
| DOWN SINGLE HEX | 单击次数 | 向下完整步数 |
| DOUBLE INVALID | 非法AB跳变次数 | 双击次数 |

`HOLD CLICK UP` 的英文标签不等于三个独立计数：其中没有额外的“点击次数”字段。向上、向下、单击、双击、非法跳变五个计数到FFFF饱和，选中旋钮后CLEAR可清除。

若只转动旋钮、没有按下SW：正常应主要增加向上/向下计数，单击和双击不应每格增加。若原始SW也随每格翻转，应优先核对该旋钮的 A/B/SW 接线和实际信号。

### 3. MASK TIME RATE

本行显示**全局效果控制目标**，并非仅选中旋钮的数据：

| 位 | 含义 |
|---|---|
| bit8..0 | 回声时间，单位ms，范围20～500 |
| bit12..9 | 颤音速度，单位Hz，范围1～10 |
| bit15..13 | 三效果开关掩码：bit13回声、bit14混响、bit15颤音 |
| bit16 | 回声当前编辑强度，0为编辑时间 |
| bit17 | 颤音当前编辑速度，0为编辑深度 |
| bit31..18 | 保留 |

默认时间150ms、速度5Hz、三效果关闭、两个编辑模式均为0时，此行是 `00000A96`。转动旋钮会改目标，但不会自动开启效果；双击相应旋钮才开关自身效果。

### 4. VOL DEP ROOM ECH

四个字节从左到右依次是：**主音量、颤音深度、混响强度、回声强度**，每项0～100，使用十六进制。

例如 `64321919` = 音量100%、颤音深度50%、混响25%、回声25%。这是控制目标；专项页为了静音而把实际输出音量平滑降至0，不会把这里记录的用户音量目标改成0。

### 5. CFG ACCEPT/APPLY

左四位为实际效果系数已应用次数，右四位为效果配置请求被接受次数。例如 `00050006` = 接受6次、应用5次。

这两个全局计数保留了单拍握手，不会因100ms刷新而漏看；到FFFF饱和，选中板CLEAR不清它们。请求包括旋钮、触摸、板载按键和蓝牙复位后的参数恢复，不能把所有增长都归因于选中旋钮。

短时间接受数与应用数不同不一定异常；若目标已经稳定而长时间没有相应应用进展，再结合事件、复位和其他状态排查。仅看到这里增长，不能证明最终扬声器已经发声。

### 6. VIEW 1～3：EC11 PCB EVENTS

最近8条关联事件，VIEW 1看最新4条，VIEW 2/3看较早4条。格式：`TTTT EE SS`，分别为毫秒时间低16位、事件码、附带状态。

| 事件码 | 含义 | 状态字节SS |
|---|---|---|
| 4x | 本号旋钮动作，x为动作位图 | bit2..0为三板在线，bit5..3为三板数据有效 |
| 50 | 本号PCB在线状态变化 | 00离线、01在线 |
| 61 | 全局效果请求被接受 | bit0请求、bit1可接受、bit2应用脉冲 |
| 62 | 全局效果系数应用 | 同上 |

4x的低四位中，bit0向上、bit1向下、bit2单击、bit3双击。例如41=向上、42=向下、44=单击、48=双击；同时发生时可以组合。

每个时钟只优先记录一种事件：旋钮动作→本板在线变化→全局应用→全局接受。同拍低优先级事件可能不出现在该板历史，全局握手次数仍独立统计。因此历史用于关联排查，不是无遗漏的逻辑分析仪。61/62会记录到各板关联历史，不能据此认定那块板或那只旋钮发起了请求。

## 九、刷新、冻结、CLEAR与数据边界

1. 键盘总线现场约1ms采集一次，主要文字约100ms刷新一次。切板时等待诊断快照追上所选板，短暂旧显示不等于新板状态。
2. 各组信息经过独立跨时钟域通道，键盘、旋钮、音频并非同一个物理时刻的采样；毫秒时间可辅助关联，不能据此证明纳秒级因果。
3. FREEZE冻结文字，不暂停键盘、蓝牙、Flash或音频处理。冻结期间旋钮仍会改变效果目标，后台事件仍会累计。
4. CLEAR清选中板的六项键盘计数、8条总线历史、对应旋钮五项计数、8条关联历史。时间基准、最后成功配置、回读验证状态不清零；健康时才清历史故障字。
5. CLEAR不清全局音符/PCM计数、效果接受/应用计数、最近页面配置结果或输出欠载标志，也不等于重新初始化。
6. 当前页没有模拟电容值、电源电压、I²C上升时间、完整实时波形或每个声部的详细元数据。不要把这些未提供的信息从某个十六进制值里推断出来。

## 十、按实际问题使用界面

### PCB1怎么按都没有声音

先看总览是否在线、数据有效、有无当前故障；再看 SENSE 是否有完整成功配置和有效回读。进入 KEYS 按键，若原始和稳定位图变化，说明至少到读键/确认这一步已有响应。菜单内 ROUTE=0属正常；退出页面和设置、松开重按再试听。

若有原始变化但变化计数、数据过期持续增加，先定位一致快照问题；若无成功配置且NACK/超时增加，先处理通信，不要仅靠提高灵敏度。

### PCB2异常敏感、托起背面也触发

先确认没有通信错误，再观察未碰琴键时 RAW、CANDIDATE、STABLE 是否自行变化。保持GSR=02，逐通道小幅提高KOR，APPLY后退出试听并记录结果。某通道异常优先调该通道，不先统一提高整板灵敏度。

页面能帮助区分“读到了触摸”与“通信失败重连”，但不能独立确定接地、供电、参考电容或安装环境的物理原因。

### 旋钮1每转一格，PCB1显示开关变化

1. EC11选1号，CLEAR后转几格，记录UP/DOWN、SINGLE、DOUBLE和INVALID。
2. 若单击/双击也每格增加，观察原始SW与滤波SW，核对接线和信号。
3. BUS选PCB1，记录NACK、TIMEOUT、REINIT、STALE及LAST ERROR BYTES。
4. 对照EC11历史4x、50和总线历史的时间，判断是旋钮事件、真实在线变化，还是仅数据过期。
5. 必要时FREEZE保留数字；切板或翻页可能解除冻结，先记录再操作。

### 参数改了但没效果

先回SENSE / VIEW 0：DRAFT变了而APPLIED没变，多数是未APPLY或应用失败；READBACK未知时不能宣称芯片已采用新值。若刚复位或断电，运行参数已经恢复默认。页面内静音，必须退出后才能试听效果。

## 十一、建议保留的排查记录

每次问题至少记录：实际位流文件/哈希、PCB编号、通道、VIEW、GSR/KOR编辑/成功/回读值、ONLINE VALID MUT、STATE、最后故障字、六项键盘计数，以及是否正在蓝牙播放或处于菜单。

旋钮联动问题另记录：五项旋钮计数、原始/同步SW状态、4x/50关联事件和大致时间。单张截图无法覆盖所有子页时，按固定顺序拍摄或抄录，避免把不同时刻的值当成同时发生。
