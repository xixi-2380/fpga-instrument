# 高山流水：主题切换

本轮只实现主题切换。界面仍为英文，未增加语言按钮或主音量调节；现有LEVEL仍是数字音频峰值显示。以main bf5df57为基线，保持音源、七音色、三效果、曲谱、MAX98357A、触摸驱动、引脚、PLL及屏幕扫描参数。

## 操作

| 入口 | 动作 |
|---|---|
| S1 | 上一常规主题 |
| S2 | 下一常规主题 |
| 两页右下THEME > | 下一常规主题，112×44触摸区域 |
| S3长按约0.8秒 | 进入隐藏彩蛋；再次长按返回进入前主题 |
| S3短按松开 | 开关当前效果；长按释放不会误开关 |
| S0 | 短按正弦，长按切演奏/参数页，保持原约定 |

默认英伦，常规循环：英伦→小猫→卡皮巴拉→英伦。彩蛋不进入常规循环；彩蛋内按S1/S2或THEME >时，沿进入前常规主题继续前/后切换。一直按住任何按钮只执行一次，S1/S2同时按下时S1优先。长按S3与普通切换恰好同拍时，S3彩蛋动作优先；同拍UI动作沿用原板载事件优先约定。

S1/S2不再直接选择笛管/簧管，S3长按不再循环效果类型。通过触屏选音色/效果，或长按S0进菜单：R1C1/C2/C3为正弦/笛管/簧管，R4C2/C3上一/下一七音色，R2C1/C2/C3为回声/房间混响/音量颤动。完整矩阵表见[instrument_ui.md](instrument_ui.md)。

主题切换保留当前页面、音色、效果类型/开关、强度/深度/速度、持音与曲谱进度。主题不是系统复位。USR仍恢复上电默认英伦并重播曲谱。

## 画面与素材

| 主题 | 实际实现 |
|---|---|
| 英伦 | 黑金配色，Great Vibes来源的真正连笔花体标题、Timbre/Effect/Amount/Room Model整词字形；淡金星座连线、星盘圆弧和金色卷饰边角 |
| 小猫 | 用户绿幕视频中原猫咪，离线去绿、裁剪成128×160、16帧，屏上2倍显示；米白暖色和典雅正文 |
| 卡皮巴拉 | 用户视频的原跳舞角色，颜色与GrabCut分割去场景背景，128×160、16帧、2倍显示；奶黄浅橙配圆润字体 |
| 隐藏彩蛋 | 从用户照片制作人物与脚的透明素材，清除字幕；演奏页完整构图独立显示于左侧，波形/电平/音符移到右侧；设置页使用右下小构图；人物固定、脚部缓慢缩放 |

动画取视频2秒起的9帧，再反向接7帧，组成16帧无硬跳变往返循环；10fps，周期1.6秒。不是原视频全长播放。动画帧/主题仅在LCD帧边界改变，不撕裂画面，不解码或播放视频原声。脚部动画128个LCD帧往返一次，当前约2.32秒。

为了片上存储，猫咪/卡皮巴拉各15种有效颜色+透明色，原生128×160；背景400×240，彩蛋源图32色；演奏页对160×120图像区按2.5倍映射，设置页按2倍显示。画面存在像素化、色阶和分割边缘取舍，应以实际仿真预览及上板为准。文字、按钮及波形仍按800×480绘制，不把整张概念图缩成屏幕。背景通过面板柔化，选中卡片与操作前景保持独立。

## 存储与时序边界

| 素材 | 初始化逻辑位数 |
|---|---:|
| 猫咪16帧4bit | 1,310,720 |
| 卡皮巴拉16帧4bit | 1,310,720 |
| 英伦装饰400×240×4bit | 384,000 |
| 彩蛋400×240×8bit（含脚部蒙版） | 768,000 |
| 三套正文/标题及花体栏目字库 | 262,144 |
| 合计（不含小调色板） | 4,035,584 |

GW5AST-138资料列BSRAM 6120Kb、340块。上表是素材逻辑数据量，**不等于综合后的块数**；还须加原音色/延迟/混响及块粒度开销。没有新增DDR控制器。必须重新综合确认同步ROM推断、BSRAM总量、DSP/LUT、35MHz像素域与61.44MHz音频域Setup/Hold；不能用旧报告代替。助手未运行Gowin、P&R或下载。

`ui_theme_art`并行同步读素材、调色板组合译码；字库并行同步读，原两级RGB/DE/HS/VS延迟保持。照片使用双读口取固定底图和脚部反变换纹理。彩蛋演奏页左侧40..439、116..415为独立展示区，使用同一ROM的220..379、84..203区域；设置页保留原命中矩形。人物前景不再被演奏波形/电平/音符卡片遮挡。动画只在像素域运行，没有音频回压或音符事件接口。主题bits55:54加入原1112位原子CDC，bit53及其余布局保持。

## 再生成与来源

直接打开根目录keyboard_adsr.gprj即可使用已提交HEX，不需安装Python、字体或ffmpeg。修改工程后应关闭旧工程再重开，确认新增ui_theme_art与theme_*.hex均列入。

可选离线生成命令（不会启动EDA）：

```text
python scripts/gen_theme_assets.py --cat <原猫视频.mp4> --capybara <原卡皮巴拉视频.mp4> --egg assets/themes/egg_cutout.png --font-dir <含LiberationSansNarrow-Bold.ttf的字体目录>
```

依赖Pillow、numpy、scipy、opencv-python-headless、ffmpeg。原视频/原照片不复制进仓库，保持只读；本次去字幕后的透明派生素材assets/themes/egg_cutout.png随工程保存，来源和提示词见assets/themes/README.md。原素材文件名与SHA256、派生素材SHA256及布局记录于assets/theme_manifest.json。脚本生成索引数据与程序绘制的星图；字体来源和子集说明见[字体说明](../assets/fonts/README.md)。

## 上板核对

1. 更新main、关闭旧工程并重开keyboard_adsr.gprj，自行综合/P&R，检查资源、ROM推断和全部时序；通过后下载本次.fs。
2. 上电应为花体英伦，曲谱照常播放。两页都点THEME >，与S1/S2比较顺序，普通循环不得出现彩蛋。
3. 小猫和卡皮巴拉应持续跳舞，手指按住主题按钮不应反复切换。检查字迹、对比度、颜色及帧循环。
4. 在卡皮巴拉等任一主题长按S3进入彩蛋，持续按住不反复切；放开后再次长按，应返回原主题。人物和背景固定，只有脚部缓慢变大/复原。
5. 先选不同音色、混响/颤动及非默认参数，按住同一行/列两个琴键切主题，检查持音不中断、无额外音符、参数不变；再测自动曲谱期间切换。短按S3仍开关效果。
6. 无触摸时可先用S1/S2/S3验证；主题实现不等于修复触摸电气或通信问题。全部结果以本次编译及实板为准。

## 纯HDL复核入口

可用原scripts/run_sim.py分别运行`--test tb_theme_controls`、`--test tb_theme_pixels`、`--test tb_theme_art`，并用`--test tb_theme_top --vendor`运行官方PLL库的顶层测试；无官方仿真库时显式改为`--behavioral-pll`，结果不能作为PLL/STA验证。每次用`--out-dir`指定新的日志目录，避免覆盖历史证据。

本轮实际使用Icarus与明确标注的行为PLL替代模型，不执行EDA。双音源对照在自动曲谱和两键持音期间仅对一侧施加主题操作，逐音频时钟比较标准I²S位流和后效果器PCM；两侧必须完全相同。其余测试覆盖四主题双页整帧、快照冻结、触摸命中、动画帧循环、脚部局部缩放、消抖/长按一次、返回前主题与既有七音色/菜单/效果/启动行为。汇总见reports/themes/2026-10-23/validation.json。


## 2026-10-25 松键与彩蛋修正

用户反馈按一下松开后持续响、彩蛋仅见脚。新增慢回升行信号模型可复现原矩阵扫描的相邻列假按键：只在早期采一次，可能读到上一列残留低电平。现在同一列的稳定早采样与槽尾采样都为低才接受，下一扫描完成后再消抖；SLOT_CYCLES至少比SETTLE_CYCLES多2拍。此改动只取自周同学蓝牙分支的扫描修正，不合并蓝牙、音量或其他新功能。

完整物理按键到I²S回归覆盖16个单键、七音色起落和长释放，尾音结束后左右数字输出归零。保留原ADSR、效果尾音及增益，不加按键超时强制截音。该仿真针对一种已复现的误识别机制，不足以证明实物现象只有这一种成因；新时序与实板松键仍须验收。

彩蛋原图只读，内置图像编辑去背景/字幕后制作透明派生素材，完整保留人物与脚。演奏页人物独立展示在左侧，实时监视移到右侧；设置页不动触摸区域。脚部缩放有安全边距，面部、抱臂和衣服区域固定。原先覆盖整屏的背景构图及预览仅代表历史版本。

单独再生成彩蛋素材：`python scripts/gen_theme_assets.py --egg-only`。不需要原视频、OpenCV或字体，不重写其他主题ROM。新证据目录：reports/release_egg/2026-10-25；baseline保留旧扫描失败与原音源通过记录，final保存修复后检查。
