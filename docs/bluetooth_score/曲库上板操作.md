## 第二颗Flash与引脚

用户已授权第二颗U7全部用于曲库；首版驱动只使用所需2.125MiB区域，其余未使用。U4配置Flash不接管。

| U7功能 | 球位 |
|---|---|
| CS# | L25 |
| CLK | P20 |
| IO0/MOSI | N21 |
| IO1/MISO | T22 |
| IO2/WP# | R22，保持高 |
| IO3/HOLD# | R20，保持高 |

N21取消原ready诊断LED用途。其余四个流水/锁定指示保持；N23按键LED保留，顶层逻辑编号由led_n[5]改为led_n[4]，物理脚仍是N23。不能把旧N21灯义继续当作ready判断。Flash共用线路上若有物理LED，可能随总线变化。

生产SPI为1MHz，50MHz参考域CE驱动。上电仅读ID、状态及目录，不自动擦写、不自动播放。当前只有EF4018兼容配置开放写入；未知ID或保护状态进入只读/错误，不修改状态保护寄存器。如果实际ID不同，请先提供读回ID和芯片丝印，补充对应配置后再验收保存功能。物理核心板版本和电气仍须对照原理图确认。

USR只复位FPGA，不等于切断NOR供电。驱动先轮询仍在进行的擦写，再读JEDEC，等待有超时；Flash恢复不阻塞手动演奏。此路径已有线级忙状态模型检查，真实忙时序仍待实板确认。

## 建议验证顺序

1. 最新11:27报告参考43.703/目标50、音频40.291/目标61.44、像素25.897/目标35MHz，仍未闭合。应先修复具体关键路径，再由用户重新综合/P&R，检查全部Setup/Hold、RAM推断和利用率；归档位流仅用于追溯，不作为合格时序版本。帧CE寄存化、音符高亮与力度读取分级不等于STA通过。
2. 下载后检查上电和USR均静音待机；16手动键、七音色、触摸、音量和效果器保持正常，空闲数字输出归零。Flash失败不得阻塞手动演奏。
3. 进入设置页 `more`，观察ID/ERROR。仅看到目录为空不代表芯片已支持；未知型号时不可把RAM下载成功当持久保存。
4. App先连接模块，再手动HELLO。应报告4096条、16声部；扩展显示真实ID与写状态。先用小星星伴奏版验证RAM多声部及三效果器，再进行一次保存。
5. 选择S001..S032，下载并等待RAM COMMIT。新App若曲库可写，会继续保存该编号，替换已有曲谱；须等“已持久保存”。Flash不可写时显示RAM完成、断电不保留，仍可主动播放。
6. 停止后在FPGA more选择另一编号、SAVE，再测试LOAD/PLAY/PAUSE/RESUME/STOP。断开手机、USR复位后列表应恢复，RAM不应自动播放；从琴端PLAY可先加载再播放。
7. 删除需两次激活DELETE；首次只确认，BACK取消。验证删除后复位不再出现该条目，其他曲目保持。
8. 用户在明确测试曲目上做存储中断、掉电恢复、32首满库替换、断线重连及至少20次循环。保留源码/位流哈希与新报告，避免把旧位流反馈算作当前实现通过。

## more操作

触摸固定字符位置与矩阵动作一致。进入设置页的方式保持S0长按；设置页右下附近增加more，矩阵R4C4也进入more，原R1C4仍返回演奏页。

| more矩阵键 | 动作 |
|---|---|
| R1C1 / R1C2 | 上一 / 下一编号 |
| R1C3 / R1C4 | LOAD / PLAY |
| R2C1 / R2C2 / R2C3 | PAUSE / RESUME / STOP |
| R2C4 | SAVE当前RAM到选中编号 |
| R3C1 | DELETE，第二次确认 |
| R3C2 或 R4C4 | BACK回原设置页并取消删除确认 |
| R3C3 | INFO切换缓存任务号/音符数，十六进制显示 |

more期间手动键不发音，自动曲谱仍经原音源、全局效果和音量输出。退出后仍需全松键再演奏。所有存储操作要求停止播放，暂停也须先STOP。选择、播放控制和Flash事务由独立模块负责，UI只发动作。

App任务等待可取消，但已经启动的Flash任务可能继续；重连原模块后点“查询未完成任务”。FPGA复位或任务被替代后可能明确返回结果未知，此时刷新目录并核对编号/CRC。不要用新的序号重复发起擦写来猜结果。
