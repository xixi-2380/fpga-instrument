# 蓝牙 MIDI 多音色实现

基线：a8f38e055e351c65b53ff087bd403de8dcae0302，目标分支codex/integrated-instrument。本次保留2秒逐声部松键延音、20Hz颤音、快速同键尾音、PCB易读设置页、上电静音、73个球位及50/61.44/35MHz时钟。

## 操作

使用0.4-midi-timbres App导入Format0/1、PPQN的.mid或.midi。默认“按原谱音色”，选择轨道、通道和移调后转换；也可选择16种统一旋律音色。鼓轨不跟随统一音色或移调。勾选“排除第10通道鼓轨”可排除不支持的鼓键。超音域、超4096条、踏板展开后超过16个同时活跃音符、毫秒舍入后零时长等会报错，不自动丢音。

新版与旧固件握手后会显示仅旧模式；旧模式应选择“旧协议：琴端统一音色”并排除鼓轨，重新转换。旧App仍可向新固件上传原8字节曲谱。新格式播放时面板选音色只影响后续手动演奏；旧格式保持按面板音色起音的历史行为。

琴端设置页每页8种旋律音色，点击PAGE按钮翻页；翻页同时选中另一页相同卡片位置。原S0/S1/S2/S3、旋钮和AUX禁用状态保持。鼓组不加入手动菜单。

本环境没有原开发签名私钥。交付APK使用新的本地开发签名，不能直接覆盖旧签名App；安装前先处理旧App中尚未确认的Flash任务，再卸载旧App安装新版。私钥不发布，不承诺沿用原签名。

## MIDI转换规则

通道默认Program0（钢琴）、CC7=127、CC11=127、CC64关闭。每次Note On冻结音色和起音力度；Program Change不重设已有音符。同通道跨轨共享状态，按tick、轨道号、原事件次序稳定处理。轨道/通道筛选仅筛音符，控制状态和全局速度图仍保留。

CC64>=64表示踩下，松开时结束已离键音符；曲尾仍踩下则在全曲EOT结束。踏板不延长鼓音。CC7/11按最近整数换算起音力度，0音量音符在完成配对后排除；持音期间音量变化不重写已有音符。弯音、触后、其他未支持控制、非默认Bank Select和SysEx会提示简化。

零基GM Program映射：0～7钢琴，8～15颤音琴，16～20管风琴，21～23手风琴，24～31吉他，32～39贝斯，40～41小提琴，42～43大提琴，44～55弦乐合奏，56～63小号，64～67萨克斯，68～71簧管，72～79笛管，80～87主音，88～103铺底，104～107吉他，108～119颤音琴，120～127主音。民族及特殊音效提示近似映射。精确表及鼓键在Timbres.java。

## 蓝牙协议

帧头VERSION仍为1，CRC16、SEQ停等、重传和旧HELLO不变。HELLO保留20字节及原features位，生产报告4096条/16自动声部/MIDI21～108。

新增0x46无载荷查询，成功响应固定8字节：status、format_mask=3、timbre_count=26、melody_min=21、melody_max=108、drum_min=35、drum_max=59、reserved=0。鼓键范围有空洞，须以上表为准。未知命令表示旧固件，不自动把多音色曲谱降级。

新增0x14启动扩展上传：note_count:u16、CRC32:u32、format:u8=1，共7字节。旧0x10仍启动format0上传。两者成功响应均为status+next_index:u16。DATA0x11按本次格式解释，推荐16条/包。format1载荷为索引2字节+192字节记录，共194字节。多字节均小端。

|记录偏移|字段|
|---:|---|
|0～3|start_ms u32|
|4|MIDI旋律音高或原鼓键 u8|
|5|velocity u8，1～127|
|6～7|duration_ms u16，1～65535|
|8|timbre u8，0～25|
|9|原channel u8，0～15；鼓为9|
|10～11|保留，必须0|

鼓键、音色与固定鼓时长必须一致；其余通道不能使用鼓音色。排序、总时长3600000ms、最大重叠16与整曲CRC由手机和FPGA校验。CRC32覆盖实际8或12字节记录。数据包两遍检查后才写RAM，非法包不部分提交；重复SEQ不重复写。

内部RAM扩为96位，song_format随保存/载入传递；legacy记录只对低8字节计算CRC。调度器为每个活跃身份保存5位音色，恢复时重放原值。参考/音频域CDC事件29位：legacy1+tone5+kind2+id7+pitch7+velocity7，背压时整个事件稳定。旧ROM曲谱格式保持64位并零扩展音色。

## Flash兼容与恢复

32首逻辑曲目、33个64KiB物理槽和目录扇区地址保持。4096条扩展记录占49152字节、192个数据页；页边界可以落在一条记录中间，保存和载入继续剩余字节。目录元数据byte19保存record_format（0旧、1新），名称等原字段不移位。

目录头格式版本1只含旧曲，版本2可混存两种记录。首次保存新曲时，利用原双目录、generation、CRC和DONE提交标记升级；新固件读取两种版本，上电和读取旧曲不写Flash。旧固件不能读取升级后的版本2目录。升级失败/断电应保留旧目录，损坏数据不能成为有效RAM曲谱。没有自动清保护、解锁、整片擦除或改变写入白名单。

## 验证与交付边界

报告在reports/midi_timbres；最终汇总明确列出测试配置与源码哈希。组件试听WAV来自实际DDS和包络RTL按48k样本步进，排除生产混音、效果、限幅与I²S，不作为实板试听或板级延迟测量。整机测试使用明确标注的行为PLL及ODDR/GSR替代模型，只验证逻辑。

本轮不运行Gowin/STA或烧录。基线已有639个Setup违例、0个Hold违例，不代表新源码时序结果。新源码没有匹配位流，旧.fs不用于本次修改验收。使用新GPRJ重新打开工程，用户后续自行综合、P&R、资源/STA及实板音质验收。

复现验证：准备tools/mingw64仿真器和JDK后运行 python scripts/run_midi_timbre_tests.py --out-dir reports/midi_timbres/recheck。默认将4096条容量（HALF=4）与生产1MHz跨页24条分开验证；--production-full-flash可另跑非常慢的满容量1MHz配置，本次未完成该配置。Android构建需要Platform35与Build-tools35.0.0、JDK，使用android/build_apk.py；工具运行时、SDK与签名私钥不随源码交付。
