# 键位自定义与演奏录制回传（0.5）

基线：`86711a306017598fa2f965e578fb04ca3bd9fe81`，目标分支 `codex/integrated-instrument`。这是源码及软件/RTL交付；不包含本版位流、STA、实板试听或手机蓝牙实测。

## 使用

1. 更新FPGA源码并自行完成综合、时序验收和下载，再安装 `GaoshanScore-0.5-performance.apk`。App沿用0.4开发签名；其他签名版本不能直接覆盖安装。
2. 配对SPP模块、连接、验证FPGA通信。旧固件仍可使用原有曲谱功能，新功能入口禁用。
3. 点击“读取琴端键位”，选择PCB 1～3及琴键1～12（CH00～11），编辑音高和音色，点击“暂存当前键的编辑”。多个键可以选择相同音高。
4. 全部编辑完成后，松开所有琴键，点击“应用整组键位”。应用与读回核对完成后立即生效，但不掉电保留。
5. 如需持久化，点击“保存当前配置到Flash”，再点击“查询键位保存结果”。只有任务状态成功才表示读回校验和原子提交已完成。恢复默认只应用到RAM，保存需另行操作。
6. 手机点击“开始录制”，或在琴端菜单的MORE页点击REC START。开始前松开全部键；已有录制在手机弹窗确认，琴端需再次点击REC START确认覆盖。琴端离开MORE或点击REC STOP取消待确认覆盖。
7. 手机或琴端停止录制，等待“可回传”（状态5），点击“回传 / 继续回传”。完成CRC核对后点击导出MIDI，通过系统文件选择器保存。取消导出不清空录制；完成回传后断开蓝牙仍可导出手机中的数据。

琴端录制最多4096个音符或1小时，内容位于独立RAM，复位丢失；断开蓝牙继续录制。App同一次运行中保留已下载前缀，重连同一段录制后可继续；结束App后可从琴端重新完整读取。4096条在9600bit/s下逐条回传需要数分钟，进度以确认记录数为准。

## 演奏语义

- 默认36键为C4～B6，全部跟随全局音色。自定义范围MIDI21～108；固定音色0～15，31表示跟随全局。鼓组不参与键位编辑。
- 手动音符身份始终是物理键ID60～95；映射音高与身份独立。同音高不同键各自松开，LCD按物理键高亮，声像依据实际音高。
- 起音时锁定音高和音色，后续预设变化不改变已发声音符或旧尾音。记录的是音源接受的手动起音和松键，包含实际起音力度，不是PCM音频；不记录效果器、尾音、旋钮轨迹及物理声部被占用后的实际波形。
- 录制期间禁止应用/保存键位、上传、自动播放和曲库任务；允许改变全局预设影响后续手动起音。读取配置、状态和诊断不阻塞音频。
- 手动停止时关闭所有未松开的录制音符；同毫秒起落最短计为1ms。第4096次起音填满容量后自动结束并关闭持音，保留数据、明确报告“容量已满”。达到1小时同样自动结束。
- 记录完整接受的手动演奏事件，超过16个自动播放逻辑声部也不丢弃。重新导入时仍检查琴端的16声部、4096记录、最长单音65535ms及总时长限制，超限报错。

## 蓝牙扩展协议

沿用A5 5A帧、V1、原序号/CRC16与整包去重规则，响应命令为请求命令或0x80；所有响应首字节为错误码，成功为0。旧HELLO和旧命令长度不变。以下整数均为小端，长度含响应首字节；错误响应恒1字节。原曲谱12字节记录与本节录制12字节记录是不同格式。

| 命令 | 请求 | 成功响应 |
|---|---|---|
| 0x50 能力 | 空 | 12B：0、版本1、键数36、最低音21、最高音108、旋律音色数16、容量u16、最长毫秒u32 |
| 0x51 读键 | 键索引u8 | 4B：0、索引、音高、音色 |
| 0x52 暂存开始 | token u32、72字节映射CRC32 u32 | 1B |
| 0x53 暂存键 | token u32、索引u8、音高u8、音色u8 | 1B |
| 0x54 应用 | token u32 | 1B；36键全部提供、CRC正确且空闲时整组原子应用 |
| 0x55 保存 | 当前映射CRC32 u32 | 3B：0、任务ID u16；仅表示任务被接受 |
| 0x56 保存/配置状态 | 空 | 16B：0、任务ID u16、任务状态u8、错误u8、任务映射CRC32 u32、标志u8、RAM映射版本u16、当前映射CRC32 u32 |
| 0x57 默认映射 | 空 | 1B；仅应用RAM |
| 0x60 / 0x63 录制状态 | 空 | 20B：0、状态u8、录制ID u32、数量u16、经过毫秒u32、记录CRC32 u32、结束原因u8、本地操作错误u8、保留u16=0 |
| 0x61 开始录制 | 空 | 5B：0、新录制ID u32 |
| 0x62 停止录制 | 空 | 1B；等待状态5再读取数据 |
| 0x64 读取一条 | 录制ID u32、索引u16 | 20B：0、录制ID u32、索引u16、条数u8=1、录制记录12B |
| 0x65 清空 | 录制ID u32 | 1B；录制/收尾/校验中拒绝 |
| 0x66 录制能力 | 空 | 8B：0、版本1、容量u16、最长毫秒u32 |

映射CRC覆盖按键0～35排列的72字节，每键为音高u8、音色u8。录制记录为起始毫秒u32、持续毫秒u32、音高u8、力度u8、音色u8、物理键索引u8；CRC覆盖按起音顺序的实际记录字节。CRC32沿用IEEE初值FFFFFFFF、反射多项式EDB88320、最终取反。

任务状态：0无任务、1进行中、2成功、3失败。0x56标志bit1:0为启动配置状态（0空白默认、1有效、2损坏回退、3容量不支持或读失败），bit2为空闲就绪，bit3为允许配置保存。保存结果须同时核对任务ID和任务映射CRC，不能只看当前映射CRC。

录制状态：0空、1录制中、2关闭持音、3/4计算CRC、5冻结可读。结束原因：0未停止、1手动、2容量、3时长、4自动任务占用。录制ID、数量、经过时间和CRC共同识别断点回传对象；内容不匹配时从头读取，不拼接旧录制。

## Flash与跨域

原歌曲空间0x000000～0x21FFFF保持。新增配置扇区0x220000与0x221000；仅JEDEC标准密度字节0x16～0x18开放新配置区，容量不足/未识别时允许RAM映射但拒绝持久化。

每个副本88字节：偏移0为KMAP魔数（u32=0x50414D4B，定义本版固定布局），4为递增generation u32，8～79为映射，80为前80字节CRC32，84为DONE标记（u32=0x454E4F44）。上电扫描两份，选CRC/范围/提交标记均有效的最新generation，比较支持计数回绕；不写入、不迁移、不擦除。

保存只擦除非当前副本的4KiB扇区，写入84字节正文并读回，再写4字节提交标记并再次读回。共享原SPI驱动，由服务层按完整任务仲裁缓冲区和总线；失败保留旧副本。不发送状态寄存器解锁或整片擦除命令。

键位、请求、响应和保存快照使用完整载荷握手跨域；状态使用原子快照。录制RAM位于音频域，直接观察已接受事件，不对音源施加背压；停止后以逐字节CRC扫描冻结数据。新逻辑不进入原每声部16拍渲染流水。

## MIDI导出

SMF Format 1、PPQN1000、速度1000000微秒/四分音符，使1tick等于1ms。包含速度轨及36条物理键轨。物理键k使用端口k/15，以及跳过鼓通道的第k%15个旋律通道；端口元事件0x21保留独立通道状态，外部播放器需支持MIDI端口元事件才能完整区分所有声部。

设备0～15音色的GM零基Program依次为：`80,73,68,42,0,24,11,19,33,40,48,56,65,80,88,21`。每次起音前写Program Change及序列器专用元事件0x7F，载荷为ASCII `GSKM`、版本1、设备音色u8。本App识别该元数据恢复包括正弦在内的原设备音色；其他播放器使用GM近似。相同时刻先处理结束，再处理起音，保留毫秒舍入导致的短连击。

## 验证与边界

自动化入口：`python scripts/run_performance_tests.py --out-dir <独立报告目录>`。报告区分Java模拟设备、RTL组件、行为时钟模型顶层、事务级NOR及真实SPI线级NOR；这些结果不等于手机无线链路、时序收敛或实板听感验收。最终证据见 `reports/performance/release/validation.json` 及源码哈希清单。
