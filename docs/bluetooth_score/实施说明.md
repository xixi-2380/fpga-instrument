## RTL 结构与时序考虑

- 接收帧使用两组独立 256×8 字节 RAM，同步读取、不整体复位。上一个已消费请求留在另一组 RAM 中，重复请求逐字节比较，避免 2048 位载荷寄存器及并行等值比较。
- DATA 先逐字节校验全部记录与 CRC32，再第二遍写入 1024×64 曲谱 RAM；失败包不部分落盘。响应缓存最多 20 字节，按字节移出，避免动态宽位选。
- 协议、去重、曲谱验证和 1ms 本地调度在 50MHz 域；23 位事件用保持载荷/请求应答跨到 61.44MHz 音频域。应答在音源真实接收后返回，静音命令等左右 I²S 锁存值清零后确认；暂停/继续/停止不重启音频时钟或功放启动时序。
- 第一版 HELLO 仅声明 1 个自动声部；手动音源仍为 32 声部。蓝牙起音会清除上一个自动音符的释放/效果尾音，此策略避免一个调度声部留下多个声音；暂停继续会重新起音。
- RGB 渲染将布局、字模读取与输出分级，RGB/DE/HS/VS 同步延迟。矩阵键盘要求稳定早采样和槽尾采样均为低才接受按键，针对跨列残留低电平模型验证；物理故障原因尚未测量确认。
- 保留原 PLL，不增加覆盖音频路径的 false path 或未经证明的 multicycle。SDC 使用 Gowin 平直命令语法，无 Tcl `if`。存储结构能否映射 BSRAM、Fmax 和实际布线耗时须由新实现报告确认。

## 验证与边界

结果入口：`reports/bt_score/validation.json`，各 TB 日志和参数位于同目录子目录。

协议核心覆盖 CRC、序号/冲突/重复、最大帧、无效 DATA 原子拒绝、上传超时、ABORT、COMMIT、播放/暂停/继续/停止；串口覆盖 9600 和 115200。2/4/8 声部组件配置共 10886 项检查通过；组件能力测试不改变生产自动声部数 1。测试中最大响应处理等待 12314 个参考时钟周期，即 50MHz 下约 246.28µs，不含 UART 线上传输时间，也不是 STA 结论。

生产频率调度测试以真实 50MHz 和 1ms 逻辑时间运行，注入每事件 50µs 消费背压；短音符起音接收误差小于 0.12ms。联合协议到音源/I²S 测试覆盖 1900ms 黄金曲谱、重复 DATA、暂停冻结、继续、自然结束和 STOP；该联合测试使用加速的逻辑毫秒、单渲染声部和缩短帧，不代表生产硬件时序。

键盘回归覆盖 16 个单键各一个声部/对应高亮、四列各自不同的四键组合，以及松键后音源、可视化与数字输出归零。效果器、完整 84 事件默认曲谱、MAX98357A 启动、英伦 UI、像素及触摸动作另有回归。数字归零不证明模拟端无底噪；按键模型通过不证明实板接线、电气或时序故障已经排除。

安卓原0.1开发APK保留为历史产物。后续用户确认P0/P1合并并分步验证，已重构为 `android/dist/GaoshanScore-0.2-dev.apk`：先独立连接模块，再手动HELLO及状态查询；36043项协议/MIDI核心和32项假传输连接状态检查通过。APK已重新构建并校验签名；随后用户确认该 App 连接、通信、MIDI 下载播放、暂停及停止正常。这是用户定性反馈，不覆盖继续、自然结束、断线恢复或长期稳定性；`reports/android_connection/validation.json` 保留构建时尚未实测的历史证据。
