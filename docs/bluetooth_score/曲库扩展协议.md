# 曲库扩展协议1

日期：2026-10-25。本文件补充原v1协议，不修改原规范。帧头、版本1、CRC16、停等序号和重复请求缓存继续沿用；整数仍为小端。普通应答最长20字节。原HELLO仍20字节，生产声明4096条音符、16自动声部、features=0x0005；bit1保持0，原COMMIT仅确认活动RAM有效。

## 命令

| 请求 | 载荷 | 成功应答长度 | 含义 |
|---|---|---:|---|
| 0x40 EXT_CAPS | 空 | 20 | 查询独立曲库能力、JEDEC与当前RAM指纹 |
| 0x41 ENTRY | 编号u8，范围0..31 | 20 | 查询一个已缓存目录项；不会逐次读取Flash |
| 0x42 SAVE | 编号u8 + 7字节短名 | 3 | 保存当前有效RAM，替换该编号；返回任务号 |
| 0x43 LOAD | 编号u8 | 3 | 载入活动RAM并共同校验；不自动播放 |
| 0x44 DELETE | 编号u8 | 3 | 原子删除目录项；调用方先确认 |
| 0x45 JOB | 任务号u16 + 操作u8 + 编号u8 + CRC32u32 | 20 | 查询最近手机任务的状态及指纹 |

所有成功应答第0字节为0。失败只返回一个错误字节，消耗普通序号并缓存。响应命令仍为请求OR0x80。SAVE短名是最多7字节可打印ASCII，末尾补0；全0时由琴端生成S001等编号。中文文件名可留在手机，不传入短名。

三个任务操作编码：SAVE=0、LOAD=1、DELETE=2。任务启动成功应答字节1..2为任务号u16，只表示任务已接受；其后可能因无曲谱、I/O或校验失败而终止。LOAD/DELETE任务指纹CRC必须为0；SAVE使用启动时实际活动RAM的CRC32。任务号可能回绕，不能单独作为任务身份。

## EXT_CAPS应答

| 字节 | 字段 |
|---|---|
| 0 | status=0 |
| 1 | 扩展版本=1 |
| 2 | flags：bit0目录初始化完成、bit1已支持芯片、bit2当前写条件允许、bit3异步任务、bit4本地控制；其余0 |
| 3 | 最大目录项32 |
| 4..5 | 最大活动音符数4096，u16 |
| 6 | 自动复音16 |
| 7..9 | JEDEC ID，24位小端；EF4018在线字节为18 40 EF |
| 10、11、12 | 最近读取SR1、SR2、SR3 |
| 13..14 | 当前曲库任务号u16，可能由琴端本地任务推进 |
| 15 | 当前曲库错误 |
| 16..19 | 当前活动RAM声明CRC32；须结合song_valid，不代表Flash已保存 |

flags是状态快照，不代替每次操作的保护检查。未知型号、保护位、WPS、CMP、暂停或忙状态均不得被App解释为可强制写。助手没有操作实物芯片；当前驱动只开放已实现的EF4018兼容配置，其他ID只读/报错，需按真实数据手册补配置后再写。

## ENTRY与JOB应答

ENTRY：字节1编号、2存在标记0/1、3..4记录数u16、5..8时长ms/u32、9..12数据CRC32、13..19短名7字节。空项其他元数据为0。单项查询不构成整个目录的事务快照；写任务期间App应等完成再刷新全列表。

JOB：字节1..2任务号、3状态、4任务错误、5操作、6编号、7..10指纹CRC32、11持久保存标志、12..19保留0。状态1进行中、2成功、3失败。持久标志仅在SAVE成功后为1，LOAD/DELETE即使成功也为0；DELETE的成功表示其目录事务已提交。

查询必须同时匹配最近手机任务的任务号、操作、编号、CRC，且该任务仍为曲库当前任务；否则返回0x28。手机断线和重新HELLO不清除正在运行的任务及跟踪记录；FPGA复位清除易失任务记录，不伪造结果，已提交目录仍恢复。后续本地/手机任务替代旧任务后也可能得到0x28。此时以目录、CRC和用户操作记录核对，不能把“查不到任务”当成保存成功。

重复的SAVE/DELETE帧由原序号/逐字节缓存直接回复，不能重复开任务。若启动应答全部丢失，App保留发送意图，重连后用EXT_CAPS最近任务号加原操作/编号/CRC尝试恢复查询；不匹配时明确结果未知，不直接重发一个新序号的擦写操作。

## 仲裁、超时与兼容

- 播放/暂停、上传、已有Flash任务或另一入口持有资源时，加载/擦写拒绝，返回0x05或任务失败0x05。首版先STOP再加载/保存/删除。缓存目录和状态可读。
- 请求启动应答不等待擦除。App每500ms查询任务，最多等待120s；取消只停止等待已启动的Flash任务，不谎报ABORT了存储。RAM上传仍可按原协议ABORT。
- 保存：有效RAM → 备用槽擦写 → 每页读回、整曲CRC → 非活动目录擦写及读回校验 → 单独编程DONE标记并读回 → 成功。失败不宣称持久保存。
- 原0.2 App可继续使用RAM命令并读取新的HELLO能力；不会自动写Flash。新0.3遇到0x40未知命令时回退RAM模式，保留当前会话及递增序号。模块连接与HELLO仍是两个手动入口。

新增错误：0x21不支持/禁止写/保护、0x22Flash超时、0x23地址或页边界、0x24Flash/目录错误、0x25Flash忙、0x28任务结果未知。原0x05状态不允许和0x09CRC失败继续保留其含义。

组件集成时，裸core/link默认LIBRARY_EXTENSION=0，缺少后端时对0x40..0x45返回未知命令，防止悬空等待。生产keyboard_top显式开启为1并连接score_services；不是仅修改HELLO字段就宣称存在曲库。

## U7磁盘格式

仅使用U7的0x000000..0x21FFFF；U4配置Flash不接入此驱动。目录A=0x000000，B=0x001000，各占独立4KiB扇区。数据基址0x010000，33个64KiB物理槽，编号0..32；每首最多32KiB有效数据，32逻辑目录项加1备用槽。没有全盘格式化或整片擦除命令。

目录有效区1056字节：32字节头 + 32×32字节项。头0..3为FSC1，4格式1，5目录数32，6..7为0，8..11代数u32，12..15目录CRC32，16..19提交标记ASCII DONE，20..31为0。CRC为标准IEEE CRC32，计算头0..11及20..1055，排除CRC和提交标记自身。

每项：0存在0/1、1物理槽、2..3记录数、4..7时长、8..11曲谱CRC、12..18短名，其余0。曲谱沿用8字节记录。先写未提交目录，提交字节保持FF，核验后独立编程DONE；复位只选择标记与CRC均完整的更新代数。覆盖/删除提交前的当前目录与其数据不动。空Flash只读扫描，不自动格式化；两个非空目录均坏时报告0x24，不自动擦除。

实际芯片仍需用户只读确认。已实现的页大小256字节、4KiB擦除、状态保护与标准SPI命令依据[Winbond W25Q128JV Rev G原厂数据手册](https://www.winbond.com/resource-files/w25q128jv%20revg%2004082019%20plus.pdf)；这不证明板上实际就是该型号。

导出的U7数据可离线检查：`python scripts/inspect_song_flash.py 导出文件.bin --output 检查结果.json`。该脚本只读文件，独立验证目录、32首数据CRC、音符格式、复音与时长，不连接烧录器。
