## 2. 已确认的问题与约束

1. `src/config/synth_config.svh` 的 `GAIN_SHIFT=5` 使每个声部固定乘 1/32。所有七张波表峰值归一到约32767，单音满包络经混音转换后峰值约1024，即约 -30.1dBFS；实际持续阶段、力度和音色会进一步降低电平。
2. `src/master_volume.sv` 的100%为单位增益，只保留原始电平，未补偿1/32衰减。100%不是功放额定功率百分比。
3. 混音器及三效果器当前接口为16位。直接取消前级衰减可能先在混音出口削波，后级降低音量无法恢复。因此首轮保留内部余量，在效果器之后以宽位运算补偿。
4. 当前波形显示采用X8放大，最终峰值监测和波形显示刻度必须区分；提高音频增益后不能把显示饱和误判为真实削波。
5. 最新下载版包含既有时序风险记录。`audio_quality_plan.md` 引用的历史报告列出音频/像素域违例；它不是本次新测得报告。软件建模可以先开展，响度实板验收必须以源码匹配的新STA满足要求为前提。

保留原采样率48kHz、音频时钟61.44MHz、参考时钟50MHz、显示时钟35MHz、PLL与GPIO。MAX四线、蓝牙P24/P23/P21及触摸/矩阵映射不动。不通过宽泛false path、未证明的multicycle或改低工作频率掩盖时序问题。

## 3. 技术路线与初始候选

建议通路：

```text
原音源 / 40位混音 / 16位效果器
    → 宽位固定增益补偿
    → 前瞻峰值限幅
    → 用户0～100%音量
    → 最终16位量化与饱和保护
    → 原frame_buffer / I²S
                └→ 同一最终PCM供波形与电平观察
```

限幅仅在峰值接近阈值时衰减，不按按键数量归一化，也不把安静尾音自动拉到目标响度。用户音量放在限幅之后，保持调低音量的行为明确；不得通过限幅器的自动补偿抵消用户调小音量。

| 参数 | 首轮模型候选 | 冻结依据 |
|---|---|---|
| 固定补偿 | 16倍、24倍，原1倍为对照 | 七音色/和弦峰值、限幅深度、试听 |
| 补偿后位宽 | 建议24位有符号，乘法另留完整中间位 | 最坏输入、符号扩展、舍入界限 |
| 数字峰值上限 | -1dBFS附近，约满幅89% | 样本峰值和定点误差；不宣称模拟true-peak保障 |
| 前瞻长度 | 32/64/128采样 | 48kHz时约0.667/1.333/2.667ms，比较低音失真、瞬态与演奏延迟 |
| Hold/Release | Hold 0/5/15ms；Release 40/80/120ms | 减少增益抖动，同时避免持续压低下一音 |
| 用户音量 | 保留5%步进、0～100及现有平滑 | 0精确零、单调、无突变、静音不释放声部 |

以上是比较集合，不是行业标准参数，也不是全部组合都必须跑；先用代表用例筛选，再扩展验证。16倍/24倍在单音满包络时分别约为数字满幅50%/75%；不据此填写实际瓦数。

主要算法参考 Signalsmith：求允许增益、窗口保持、有限长度平滑和音频延迟严格对齐，采用只衰减的增益包络。不能只对瞬时比较结果做普通平滑后就承诺没有峰值越界。DaisySP的轻量峰值跟踪＋软限幅用于资源和听感对照，不同时叠加两套限幅器。JUCE的两级压缩＋最终截断作为另一类参考，不将硬截断作为主要响度手段。

首轮保留内部16位效果器，所以后级补偿无法恢复此前丢失的低电平精度。若放大后尾音量化误差明显，作为独立证据记录，再决定是否开展内部位宽改进，不一开始扩大全部效果器RAM。

## 4. 必须先解决的清空和调度语义

当前 `bluetooth_audio_bridge` 每次自动On都进入CLEAR，`flush`会清理声部、效果器和frame_buffer。前瞻加入后若继续用同一个reset清空全部输出，持续1ms的短音可能尚未走完64采样前瞻就被下一音删除。

实施前冻结以下内部分类；必要时扩展内部事件原因及CDC载荷，但不修改v1线上帧格式和HELLO能力：

| 触发 | 计划语义 |
|---|---|
| 自动换音/起音 | 保留当前单自动声部策略；声部/效果清理与输出队列清空分离。已经排定的前瞻音频继续按采样时间线输出，不因下一音删除 |
| PAUSE、STOP、上传/手动接管 | 立即丢弃待播前瞻和输出缓存，取消旧valid；实际左右I²S静音后才确认，防止缓存复活 |
| 自然曲终 | 识别最后有效音频的输出时间，先排出正常延迟的数据，再完成曲终清理；不能无条件把最后N个采样删除 |
| 全局复位/失锁 | 清理队列、增益控制及输出状态；保留原启动保护 |
| 用户静音 | 保留声部/播放进度和音量渐变，最终输出精确零；后续内部换音清理不能把音量恢复成100% |

`synth_core` 的输出队列与frame_buffer也必须按上述分类复位，不能仅在限幅器内部区分而仍由旧engine_reset把最终缓冲清空。保持I²S时钟连续；新缓冲预热期间按定义供零，正常运行每采样输出一对。一次硬清理后，不得重新输出旧乘法流水线的尾部结果。

固定音频延迟与事件握手延迟分别核算。不能把1～3ms前瞻等待塞进每次On的ready握手，导致1ms调度超时。暂停冻结的音乐位置、继续后的剩余时长、自然结束和实际发声时间需有带延迟的独立参考。

## 6. FPGA实现与时序预算

- 使用61.44MHz音频时钟与48kHz采样使能，不增加内部派生时钟或CDC。已有每采样1280周期；原渲染预算544周期，新级的实际完成周期以TB测量冻结。
- 新增算术每采样的计算延迟初始目标不超过128个音频时钟周期，前瞻的N个采样固定延迟另计；仍须证明加上旧渲染/效果器/音量后，按时交付frame_buffer。必要时调整串行调度，不靠增大帧周期容纳。
- 禁止将窗口最大值并行展开成长比较链；采用可证明有界的逐拍窗口处理或定长结构。定点倒数采用小表/分段或顺序算法，避免变量组合除法；计算必须保守舍入以满足峰值界限。
- 音频延迟RAM同步读写，不做整块reset；用有效计数/代数屏蔽旧数据。64×24的纯音频延迟数据为1536bit，峰值窗口、平滑状态、系数等额外资源单独估算；不能把1536bit当作全部资源占用。
- 正负满幅、最小负数取绝对值、移位前符号扩展、乘法中间位、最终饱和和非零小增益都须明确位宽。零输入、静音和清理后保持精确零，不引入抖动或AGC来抬高空闲输出。
- 按当前RTL接口和实际Gowin RAM/DSP推断结果评估资源；模型或仿真不填写Fmax、BRAM块数或布局布线耗时承诺。已有音频/像素时序问题单独跟踪。

## 7. 验收用例与证据

| 用例 | 重点检查 |
|---|---|
| 单音七音色、蓝牙低/中/高力度 | 未限幅区域增益准确；保留力度差异、包络和正常谐波 |
| 2/4/8/16/32声部、同相最坏负载、反相抵消 | 不溢出回绕；峰值守界；普通和弦不长期深压缩；抵消后的静音稳定 |
| 最低音持续、高音短瞬态、密集重复音 | 低频调制失真、增益抖动、起音损失和限幅恢复可量化 |
| 回声/房间/颤音及类型/强度切换 | 尾音、干湿混合峰值和释放过程正确，不把原颤音当限幅抽吸 |
| 1ms短音串、连续On、pause/resume/STOP、自然结束、上传接管 | 固定延迟正确、无事件丢失、无短音被清空、无末尾样本误删或旧缓存回放 |
| 音量0/5/50/100与持音连续调节 | 0精确零，幅度单调、变化平滑，音量状态不因flush丢失 |
| 全局复位、失锁、清理与valid间隙 | 缓存预热有定义、输出无未知值，每帧正常交付且I²S左右一致 |
| 实屏与外部I²S解码 | 显示取最终PCM，X1/其他刻度明确，显示截顶与音频限幅分别判断 |

每个候选保存参数、源文件SHA256、峰值/RMS、限幅衰减深度和占比、硬饱和次数、零输入残留、延迟和处理周期。频谱/THD比较使用固定频率与一致窗口；正常音色谐波不能误算为故障。饱和器作为兜底，正常测试若经常触发，需要回查增益/限幅设计而不是宣称保护成功。

产物计划保存到 `reports/audio_output_gain/<阶段>/`：定点模型向量、HDL日志、原始幅度和匹配响度WAV、图表及validation.json；独立报告不能覆盖既有失败日志。以原始PCM/I²S证明数字结果，再由用户测量固定负载上的差分音频有效值并结合条件估算功率，不以D类开关波形峰值或屏幕百分比当作实际音频功率。

## 8. 成熟方案参考

- [Signalsmith算法说明](https://signalsmith-audio.co.uk/writing/2022/limiter/)：前瞻、窗口保持、平滑、释放与信号延迟的对应关系，作为主要结构参考。
- [Signalsmith Basics源码](https://github.com/Signalsmith-Audio/basics)：具体实现参考；移植前核对所选版本和许可证，记录引用，不能直接把C++效率视为RTL时序。
- [DaisySP Limiter源码](https://github.com/daisyaudio/DaisySP/blob/master/Source/Dynamics/limiter.cpp)：轻量峰值跟踪、增益控制和软限幅对照。
- [JUCE Limiter文档](https://docs.juce.com/master/classjuce_1_1dsp_1_1Limiter.html)：两级压缩和最终截断的另一种取舍。
- [FluidSynth版本记录](https://www.fluidsynth.org/wiki/ChangeLog/)及[设置说明](https://www.fluidsynth.org/api/settings_synth.html)：2.6起加入输出限幅，主增益与可选限幅配合；不是所有旧版默认启用的功能。
- [ADI SigmaDSP RMS Limiter](https://wiki.analog.com/resources/tools-software/sigmastudio/toolbox/dynamicsprocessors/limiter)：持续电平控制参考；RMS指标不能替代样本峰值验证。

当前不预先承诺最大功放瓦数、SNR、THD、时序闭合或主观音质改善幅度；候选参数由上述证据逐项冻结。
