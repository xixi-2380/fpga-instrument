# 模块接口和固定周期约定

## 时钟与复位

参考 50 MHz；PLL 1：IDIV=1/FBDIV=1/MDIV=16/ODIV0=25，输出 32 MHz、VCO 800 MHz。
PLL 2：IDIV=1/FBDIV=1/MDIV=24/ODIV0=12.5（整数 12、1/8 分数值 4），输出 61.44 MHz、VCO 768 MHz。
PFD 分别为 50/32 MHz，满足工具要求的 19..81.25 MHz。原 50→96→61.44 MHz 候选因 PFD 不合法已废弃，错误报告保留。
使用 GW5AST-138 的 PLL 原语，内部反馈、静态配置；没有组合逻辑派生时钟。
PLL 2 在 PLL 1 连续稳定 100000 个 50 MHz 周期后解除复位；第二级再资格判断 2 ms。
LOCK 低会异步断言安全复位，释放经过本域两级同步。上电 POR 计数器使用 Gowin 可综合寄存器初始化。
失锁时直接静音；恢复必须重新锁定并走完整启动流程。

## 音频周期

所有音频 RTL 在 audio_clk 上升沿运行。BCK 是寄存器输出，正常高低各 20 个周期。
每 1280 周期一立体声帧。bit_index 0..15 为右、16..31 为左。
frame_ce 与右声道 MSB 的第一个下降沿同拍；DIN/WS 此时更新，上升沿采样。
复位将 BCK 置高、WS/DIN 置零；首次下降沿建立右 MSB，随后第一上升沿采样。
复位可打断当前帧，下一次运行从完整右/左帧开始。

## 数据与握手

phase 为无符号 U0.32 周相位；FCW 为每样本周期相位增量。sample_ce 每帧推进一次。
ROM 地址 phase[31:20]，4096x16 有符号 Q1.15，同步读，valid 与 ROM 输出同拍有效。
tone_gain 将输入拼接 8 个零扩展为 Q1.23；level 为无符号 Q1.16（0..65536）。
先以42位有符号乘积保存。tone_gain默认16位输出时右移29位；当前共享路径设置OUTPUT_W=24，右移21位，保留8个小数位。每声部仍使用level/65536和1/32增益，数值不变。
当前32路24位值依次符号扩展到40位累加，再算术右移8位、饱和至[-32768,32767]。截断向负无穷，仅在总和转DAC时舍掉这8位；每声部峰值约1024个DAC码，四路同时最大约4096，32路接近满量程，不增加额外归一化。

frame_buffer 使用 sample_valid/sample_ready、sample_l/sample_r 成对接收。
valid && !ready 时生产者必须保持 valid 和左右数据；旧715920f四声部流水线在第4周期提交；当前32声部共享流水线在frame_ce后第517周期交付下一帧样本，永远有空闲缓冲，TB 检查此假设。
每帧先消耗旧 pending 对，再接收本拍新样本；边界同拍交付的样本属于下一帧，无直通旁路。
缺样本发零，除预期初帧外置位 sticky underrun；复位清除标志。

启动先完整发送 480 帧零码，在索引 480 的帧边界开启 PA，后续 240 帧令 level 从 0 线性增加至 65536。
一帧缓冲使数字淡入样本晚一帧到串行输出。当前左右声道发送同一混音样本；旧D1的channel_mode左右隔离模式属于已归档入口。各声部FCW通过下述音符事件接口更新，不直接接异步多位控制。

## 2026-10-15：单声部分离接口（历史，已被下述四声部接口替代）

keyboard_top只做板级连接。keyboard_core保留矩阵行列、同步/去抖、鬼键抑制、按键优先级及key_fcw映射；synth_core接收通用单声部音符事件，不引用key_row/key_col、16键位图、selected_key或键位表。ADSR默认值移至原synth_config.svh，数值不变；keyboard_config.svh仅定义矩阵扫描参数。

| 信号 | 方向 | 约定 |
|---|---|---|
| frame_ce | 音源→输入适配器 | audio_clk域的帧采样使能，每1280周期一次；仅作CE，不能当时钟 |
| note_ready | 音源→输入适配器 | 启动静音阶段完成后允许提交音符；适配器在为0时禁止Note On/Off |
| note_on / note_off | 输入适配器→音源 | 同一audio_clk域，在frame_ce有效的上升沿采样；一次事件只覆盖一次帧边界，不接受随意异步脉冲 |
| fcw[31:0] | 输入适配器→音源 | 无符号32位相位增量，与该帧音符事件同时稳定；无新音符时保持当前音高，Release仍使用原频率 |
| envelope_level[16:0] | 音源→观察接口 | 现有Q1.16 ADSR包络，仅用于观测；按键gate和selected_key属于输入模块 |

两模块当前同一audio_clk和audio_reset，无新增跨域路径。事件同时到达时沿用ADSR的Note Off优先级。今后串口/MIDI/其他时钟域键盘必须在输入适配器中完成原子事件跨域，不可把异步多位频率直接接入。这里只定义接口，不增加这些外设或事件队列。

note_ready是输入许可而非外部功放管脚；当前原启动控制仍同时释放note_ready与PA_EN，功放时序完全保持。USR输入、POR与PLL复位保留在clock_reset，不放入键盘映射或音源模块。用户已确认底噪为耳机阻抗问题并取消处理，未加入自动静音、待机或唤醒延迟。

## 2026-10-15：四声部并行事件接口（历史）

keyboard_core只处理物理扫描与key_note_events；矩阵位图、键位表、鬼键策略不进入synth_core。原mono_note_control文件在原位置重命名并改成key_note_events，不保留重复版本。通用音源内的voice_allocator与输入种类无关。

| 信号 | 方向 | 当前约定 |
|---|---|---|
| input_ready | 音源→输入适配器 | 原启动静音完成，允许开始发送键盘事件；与PA_EN沿用同一启动控制 |
| note_valid / note_ready | 双向 | audio_clk上升沿两者同时为1才接收事件；valid为1而ready为0时，valid及全部载荷必须保持 |
| note_on | 输入→音源 | 此次事件类型，1为Note On，0为Note Off；不再是只能在frame_ce出现的单音脉冲 |
| note_id[6:0] | 输入→音源 | 0..127音符身份；当前矩阵输出60..75，不等于声部编号 |
| note_fcw[31:0] | 输入→音源 | Note On对应的32位相位增量；Note Off仅按编号匹配，忽略FCW |
| frame_ce | 音源内部/观察 | 固定1280周期帧边界；此拍note_ready为0，其余就绪周期可接收事件，串行输出不等待控制 |
| voice_held / voice_active | 音源观察输出 | held表示当前被按住的四个已分配声部；active包含Release尾音 |
| envelope_level | 音源观察输出 | 四个17位包络的最大值；不是混音增益或单个被选中键的包络 |

接收的事件先更新声部所有权和待处理命令，ADSR与DDS在下一frame_ce统一执行；多条事件可以在两帧之间接收，不停BCK。矩阵适配器每两周期最多发送一条，选择新事件时先释放、再按下，同类按键号从低到高；已经发出的回压事件不能撤回。最新稳定键状态与已确认状态逐步收敛，鬼键清零会产生全部相关Note Off。

同一编号再次Note On复用原声部，刷新起音年龄，从当前包络重新Attack且相位连续。新编号依次选空闲、最久未起音的已释放、最久未起音的按住声部；所有权改变在帧边界同步清零该声部相位与包络后起音。年龄用有界排序而非会溢出的时间戳。被替换的旧Note Off不会误关新音符；被替换但仍按住的键不会自动恢复，需要松开重按。替换是帧边界直接换声部，没有额外偷音交叉淡化。

同一声部一帧间隔内的多次重触发合并处理。若一次On后Off都发生在帧前，保留一次起音并在后一帧释放，防止卡音；不保证亚采样周期的短事件可听。现有矩阵约3ms消抖，远大于20.833us音频帧。

每个声部独立32位相位、4096×16同步ROM、17位ADSR和24位声部输出；新增40位混音寄存输出后，样本在frame_ce后第4周期进入下一帧缓冲。所有域内控制使用audio_clk和CE，无新内部时钟或CDC。将来其他时钟域输入须先做原子事件跨域，再遵循此握手；本次未增加MIDI、串口或其他键盘驱动。

PLL、U4下拉复位、引脚、480帧静音、240帧淡入和PA持续开启策略保持；用户已取消底噪处理。无二极管矩形歧义仍释放所有声部；四声部不代表任意四键无冲突。当前资源与时序需用户重新综合/P&R确认，旧报告不作四声部验收。

## 32 声部实现规划

2026-10-15按用户“下一步规划”要求制定；以下保留当时方案，2026-10-16实施状态看文末“32声部当前实现”。功能与验证基线为715920f：四声部用户实板定性确认，7051357项HDL检查通过。下面描述拟实施行为，不替代上节当前四声部接口，不是32声部已完成声明。

### 方案与边界

保留32份独立音符所有权、FCW、32位相位及ADSR状态。第一版ADSR仍按声部实例化并在frame_ce统一更新；共享一套同步正弦ROM读取路径、一套启动包络乘法路径及一套tone_gain路径，逐声部生成24位样本，进入40位寄存累加器，最后一次截断并饱和到16位。两类乘法的实际DSP映射及ADSR常数除法/分配器比较路径的资源和时序均须用户综合/P&R报告确认，不宣称一个RTL乘法器等于一个物理DSP。

当前synth_core中的generate为每个声部实例化DDS/ROM与两类增益运算，voice_mixer是串联组合求和。直接把VOICE_COUNT从4改成32不会实现共享调度，并会放大资源和组合路径；下一版须先重构数据通路。本阶段仍只做正弦复音，不增加MIDI、音色、效果器、显示或硬件自奏入口。

### 固定帧调度预算

61.44 MHz音频时钟、48 kHz采样，每立体声帧1280周期（约20.833 µs）。拟采用16周期固定声部时隙，另预留32周期处理帧准备、最终结果交付和裕量：

| 项目 | 周期数 | 设计用途 |
|---|---:|---|
| 帧准备预留 | 16 | 锁存该帧命令/参数，等待ADSR和启动包络更新可见，清空本帧累加器 |
| 32个声部时隙 | 32 × 16 = 512 | 固定顺序遍历0..31，每声部只计算并累加一次 |
| 帧收尾预留 | 16 | 最后一次累加生效后转换、交付下一帧样本，检查完成状态 |
| 合计 | 544 | 约8.854 µs，作为包含sample_valid/ready握手的设计截止预算 |
| 帧内剩余 | 736 | 约11.979 µs，可接收后续事件；不依赖这些周期补算漏算声部 |

单声部16周期内的逻辑顺序为读取独立上下文、应用restart选择采样相位、同步ROM读取、包络与启动level相乘并右移16位、tone_gain定点运算、40位符号扩展累加和相位写回。具体周期编号由RTL及TB锁定；不能把ROM的单周期延迟、非阻塞赋值或最后一次累加/转换放在同拍而误用旧值。

1/4/32声部参数下均采用相同调度原则，预算为32+16×VOICES；32声部必须在frame_ce后544周期内完成缓冲握手，并早于下一1280周期边界。当前四声部“第4周期提交”的历史约定在共享实现中会改变，串行输出仍在下一帧发送旧pending样本，不能额外多加一整帧延迟。上述是方案预算，只有后续测试通过后才能记为验证结果。

### 事件、帧状态与一致性

- 外部事件字段继续为note_valid/note_ready、note_on、7位note_id、32位note_fcw，不加入键盘专属信息；input_ready仍表示启动许可，与现有PA启动策略保持。
- frame_ce拍不接收事件。拟在整段渲染busy期间令note_ready为0，完成后恢复接收；输入适配器必须保持valid和全部载荷。启动许可与渲染busy分别处理，不能把busy用于关闭PA或暂停BCK。
- frame_ce锁存本帧FCW、voice_restart等短脉冲和命令归属，32个ADSR在同一边界更新。后续时隙读取该帧更新后的包络/启动level；渲染结束前不变更所有权，避免同帧前半读旧音符、后半读新音符。跨域输入仍须由适配器完成原子传递，本阶段无新增CDC。
- 每个声部每帧相位只推进一次，包含空闲声部，保持现有相位约定；新身份以相位0起音，同身份重触发保持相位/当前包络。无效/空闲声部也占固定时隙并贡献零码，静音期间每帧仍须交付样本。
- 保持同编号、空闲、最旧释放、最旧按住的分配策略；第33音和被替换编号的旧Note Off须正确处理。年龄排序保留有界状态，不引入时间戳回绕。On+Off同帧间隔的语义沿用当前约定，不能因时隙重构而卡音。
- 新增的ready等待、帧归属和输出等待全部计入输入延迟；8.854 µs是渲染预算，不是端到端实测延迟。仍按原目标核对总延迟≤10 ms、争取<5 ms。

### 定点精度与输出

保留32位相位、4096×16同步正弦表、17位Q1.16包络、24位声部和40位混音。每声部仍使用1/32增益；32个同相、满包络声部接近16位满量程，不为扩声部擅自调整功放或总增益。24位有符号值求和32次至少需29位，40位累加具有余量；仍只在最终混音算术右移8位并饱和，避免先转16位再求和。
