# RCWL-9610A 超声波音量交互

本功能在 `feature/ultrasonic-volume` 分支开发，以 `main` 的 `b07c0d5` 为基线。按王开册最新要求，独立分支交付，暂不合入 main。依据用户本次提供的《超声波模块使用说明(2).md》实现；原说明作为输入依据保留，未将其电气假设写成实测结论。

## 使用行为

生产顶层默认 `ULTRASONIC_ENABLE=1`。传感器仅控制最终音量，不触发音符、不更改音色、效果器、主题、曲谱和按键含义。自动曲谱与手动演奏均受这一级音量控制。

- 复位后先等待完整 60 ms，再开始触发。Trig 高电平 20 μs，两次触发至少间隔 60 ms。
- 有效测距读数进入三点中值滤波；第一帧直接使用并初始化历史。
- 5～40 cm 控制音量，越近越大。有效距离 ≤5 cm 时为原音量，≥40 cm 时静音。
- 目标增益采用 0～256 的整数，256 表示 1.0。音频每 4 个采样向目标移动 1，48 kHz 时全范围过渡约 21.3 ms，避免直接阶跃切换。
- 上电或 USR 复位后、第一次有效测距前，增益为 1.0。未接传感器、Echo 保持低时，原演奏音量保留。
- 无回波、异常短脉冲、过长高电平、触发前 Echo 已高或越界读数：保持最后有效音量，不把异常值当成 0 cm，不更新滤波历史。
- **移开手而没有回波时，不会自动静音或自动恢复满音量。** 若上一次为静音，将一直保持静音，直到有效距离更新或复位。

| 有效距离 | 增益整数 | 幅度约占原信号 |
| --- | --- | --- |
| ≤5 cm | 256 | 100% |
| 10 cm | 219 | 85.5% |
| 20 cm | 146 | 57.0% |
| 30 cm | 73 | 28.5% |
| ≥40 cm | 0 | 0% |

映射为线性幅度，不是按听觉响度校准的曲线。有效筛选窗口是程序选择的 2～400 cm，不代表已经实测确认该型号的整个量程。按 58 μs/cm 近似换算，1 μs 量化，无温度补偿。中值滤波对稳定变化通常增加一帧延迟，另有等待下一次测距和音量过渡的时间，适合缓慢表情控制。

## 接线

| 模块引脚 | 连接 |
| --- | --- |
| Echo | FPGA U17，顶层 `ultrasonic_echo` |
| Trig | FPGA P21，顶层 `ultrasonic_trig` |
| GND | 实际 GND，共地 |
| VCC | 按实物规格供电，不能据说明书认定支持 3.3 V |

用户指定球位与只读参考 CST 的 `pin_header[7]` / `[6]` 对应。该参考将 Header 标为 3.3 V，当前生产 CST 已检查无球位重复。新增约束按 3.3 V 逻辑设置，Echo 使用内部下拉避免拔下模块后输入悬空。实物 Bank 电压与 Echo 高电平仍需确认；若 Echo 输出为 5 V，先转换至 FPGA 允许电平。

## 实现与接口

| 文件 | 内容 |
| --- | --- |
| src/ultrasonic_range.sv | 50 MHz 域：两级 Echo 同步、微秒计时、触发和异常处理 |
| src/ultrasonic_volume.sv | 仅接纳有效值的中值滤波、固定整数增益查表 |
| src/audio_master_gain.sv | 音频域：逐采样平滑、带 valid 的有符号 PCM 乘法流水 |
| src/keyboard_top.sv | 传感器接入，复用原 `rgb_status_cdc` 进行 9 位增益原子传递 |
| src/synth_core.sv | 效果器之后、frame_buffer 之前的可选音量级 |
| src/keyboard.cst、src/keyboard.sdc | U17/P21 与 Trig 输出路由预算 |
| keyboard_adsr.gprj | 新增三个生产 HDL 文件 |

参考时钟仍为 50 MHz，音频时钟仍为 61.44 MHz，采样率仍为 48 kHz。没有将 61.44 MHz 取整成 61 MHz 计时，也没有改 PLL 或创建新分频时钟。

距离换算用“每 58 μs 累加一厘米”的商/余数计数器，避免运行时组合除法。增益转换为小型固定查表。跨域的 9 位数据通过已有请求/应答快照保持，不逐位同步；任一域复位会重置握手，本地复位同步释放。消费者在快照尚未有效时使用 256，避免把跨域复位值 0 当作静音命令。

音频增益在效果器之后统一作用于同一个单声道样本，原有左右相同的输出方式保留。乘法与输出寄存分拍，`output_valid` 同步延迟，再送原 frame_buffer/I²S。增益最大 1.0，不放大或额外削波；算术右移保留有符号语义，负小数结果向负无穷取整，最多带来一个 PCM 码的舍入差。

独立 `synth_core` 默认 `MASTER_GAIN_ENABLE=0`，不需要音量控制的原调用者保持旁路；板级顶层按 `ULTRASONIC_ENABLE` 打开该通路。若要生成对照版本，在顶层将 `ULTRASONIC_ENABLE` 改为 0：Trig 停在低电平，增益级在综合时旁路。现有 S0/S1/S2/S3 不重新分配。

LCD 页面与触摸命中区域不扩展。本轮没有屏幕音量条或距离读数；原实时波形/峰值仍在超声波音量级之前采集。因此静音时仍可显示正在合成的波形。

调试仿真可观察 `keyboard_top.ultrasonic_on` 内的 `distance_cm`、`filtered_cm`、`gain_ref`、`gain_audio`、`sample_done`、`sample_valid`、`control_valid`、`error_code`，以及 `sound.master_gain_current`。这些内部诊断信号未保证综合后全部保留。

| 错误码 | 含义 |
| --- | --- |
| 0 | 最近测距成功；复位时也为 0，首次有效性以 valid 脉冲为准 |
| 1 | 等待 Echo 拉高约 30 ms 超时 |
| 2 | Echo 高电平约 30 ms 超时 |
| 3 | 脉宽短于约 116 μs，或换算后距离不在 2～400 cm |
| 4 | 准备触发前 Echo 已高 |

## 重新实现与上板

1. 下载本分支，关闭旧编辑页后重新打开根目录 `keyboard_adsr.gprj`，确认三个新 HDL 已进入文件列表。
2. 先核对供电、共地、U17/P21 接线与 Echo 电平。
3. 由用户运行 Gowin 综合、P&R，检查新报告的资源、Setup/Hold，以及 50/61.44/35 MHz 时钟约束是否满足。新增模块不会自动消除原工程已有时序问题。
4. 使用本分支新生成的 `.fs` 上板，示波器检查 Trig 20 μs、间隔至少 60 ms。
5. 在 10/20/40 cm 验证音量和回波，随后检查移开手、遮挡和重新靠近时的保持/恢复行为。
6. 验证《小星星》、手动持音/松键、七音色、效果器、触摸、主题和 USR 重启。

无新的数值 STA 或实板试听结果前，本分支只能标记“RTL/逻辑仿真已验证”，不能标记“时序收敛”或“实板通过”。

## 运行纯 HDL 测试

在工程根目录安装 Icarus Verilog 12.0 后运行：

```bash
python scripts/run_ultrasonic_sim.py --out-dir reports/ultrasonic/local
```

单独测试真实 50 MHz 分频配置：

```bash
python scripts/run_ultrasonic_sim.py --test tb_ultrasonic_range --param CLK_HZ=50000000 --out-dir reports/ultrasonic/local_range50
```

脚本读取同一 GPRJ 列表，使用相对 include，未给配置头文件额外添加搜索路径。集成测试明确使用测试专用 PLL 替代模型，非厂商 PLL 验证、非时序仿真。为控制四态仿真时间，集成 TB 将测距计时参数与 Echo 脉宽按同一比例压缩 50 倍，并将音量步进间隔从 4 改为 1；50/61.44 MHz 域时钟和 48 kHz 音频帧率保持。真实 50 MHz 测距和默认步进 4 分别由独立单元测试覆盖。这些覆盖仅存在于 TB，不进入生产工程。可用 `--simulator verilator` 运行适合双态模拟的单元测试；物理矩阵的高阻网络和未知态验收以 Icarus 四态结果为准。

本次实跑结果与开发失败记录见 `reports/ultrasonic/2026-10-25/validation.json`。
