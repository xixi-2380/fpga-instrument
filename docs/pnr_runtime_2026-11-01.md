## 本次 RTL 修改

### 限幅器：去掉宽绝对值及二次取负链

原表达式对42位乘积取绝对值，再截取整数部分，最后恢复负号。新表达式直接取有符号整数部分；负数且被丢弃的16位中存在非零位时加1，从而保持原先向零取整的规则。

signed24采样乘unsigned17增益满足绝对值严格小于2^40。本次Z3对整个[-2^40,2^40]乘积区间证明旧/新26位结果不存在反例，涵盖该乘法的全部合法输入。限幅阈值、乘法、RAM、状态机、寄存级、tag和valid交付时刻均未修改。不能直接把算术移位当作旧运算：负小数必须修正。

Yosys通用网表中原42位和26位取负单元及两个选择器消失，增加26位修正加法和低16位归约逻辑。其他两个24位绝对值单元保留。这个比较不是最终 LUT/CLS 节省量。

### PCB诊断页：私有行缓存不复位

`lines`是内部八行工作区，完整格式化后才一次发布到`display`。第7行直接用`text_q`发布，实际消费的是前七行2240位，未使用的最后320位本就可裁剪。

把原工作区写入移到独立同步进程，不再接入异步复位；写使能与旧控制器完全一致：非复位、无命令中断、building、decimal_busy为0、format_phase为2。控制状态和对外display仍保留原复位。中途中断/复位后必须从第0行重新格式化，不能把旧工作数据发布。

Yosys proc/opt通用结构中，模块异步复位FF位数9372→7132，减少2240个复位负载，总FF位数不变。控制集/CLS打包和实际布线收益要看高云新报告。

专项包括三组完整限幅器逐时钟输出/tag/增益/ready/valid对照、PCB全部外部端口对照、每一行中途复位、菜单关闭重开/冻结/随机输入、两个既有PCB测试及三组独立Python窗口模型向量。最终结果以同目录validation.json为准。

## 在 Windows 上评估实际提速

1. 先确认本机正在编译的分支、提交和未提交差异。若使用RGB版，不要用本分支整包覆盖它；可单独审查共同模块改动。
2. 基线与候选在同一电脑、同一工具版本、同一设置下分别冻结输入；本补丁没有修改GPRJ、CST、SDC、PLL、音色或声部数。
3. RTL已改，先重新综合；成功后检查实际LUT/FF/CLS/BSRAM/DSP和高扇出网络，再运行一次完整P&R。正常构建不要同时跑多个大型实现，以免墙钟比较受系统负载干扰。
4. 只有RTL和ROM等综合输入未变、网表哈希与成功综合清单相符时，才复用同目录网表只重跑P&R。禁止为省时间沿用不匹配或中断的网表。
5. 记录综合、布局、每个布线阶段及总墙钟；同时记录是否布通、Setup/Hold、TNS、最差slack。更快失败不算提速成功；未结束的运行不计为完成时间。
6. 现有日志已表明某些所谓快速profile仍无法布通，本次不盲改Place/Route/Maxfan。不要关闭Timing Driven、Hold修正或放宽频率来换取表面速度。

如果仍严重拥挤，下一轮应先按最新物理网表评估32份延音运算的共享调度、宽诊断缓冲复用与控制集拆分，而不是继续随机扫工具选项。这类较大改动需要完整音源逐拍对照和新物理报告；临近11月3日提交，不宜一次混入多项架构重写。

官方依据：Gowin SUG100 Software User Guide说明Timing Driven用于时序驱动优化，Route Maxfan偏小可能造成布线失败。实际选项以安装的V1.9.12.04配套SUG100/SUG1220为准；没有采用某组参数一定更快的假设。
