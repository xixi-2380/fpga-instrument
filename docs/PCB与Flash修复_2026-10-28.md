## 进入PCB专项设置

在设置页点击 `PCB`。原 `ULTRA` 超声波、`more` 曲库、音量和默认设置入口保留。

进入时沿用256采样音量渐变，确认最终左右PCM和串行帧已静音才显示专项页；退出时等待LCD实际离开该页再恢复音量。时钟、DSP、蓝牙和Flash任务继续运行。蓝牙曲谱可能在后台继续推进。菜单阻止手动音符时，显示真实的屏蔽标志，不把观察到的原始触摸伪装成已接受的音符。

页面顶部为 `OVERVIEW / SENSE / BUS / KEYS / EC11`，分别表示总览、灵敏度、通信、按键链路和旋钮。`PCB -/+` 选择第1至3板，EC11页同号对应第1至3旋钮。`CH -/+` 选择00至0F通道，其中00至0B为12琴键、0C至0F为4个AUX。

`GSR/KOR` 切换编辑项；`VIEW` 循环详情页0至3；`FREEZE/LIVE` 冻结/恢复显示。冻结不停止采集和故障保护。`CLEAR` 清选中板/旋钮统计与事件，不清真实故障、当前参数或Flash。

### 调整灵敏度

- 先保持GSR=02，逐通道调整KOR。GSR越大整体越敏感，范围00至0F；KOR越大越不敏感，范围01至FF。
- `- / +` 每次修改1，页面数字使用十六进制。`ALL KOR` 将当前通道的编辑KOR复制到本板16通道。
- `DRAFT` 为编辑值；`APPLIED` 为最后全部成功的配置；`READBACK` 为实际寄存器回读。整板从未成功初始化时APPLIED显示 `NO APPLIED CFG : FFFFFFFF`，备用默认值不冒充成功配置。尚未通过回读的值（包括四通道分组内任一未验证通道）显示 `UNVERIFIED READ : FFFFFFFF`，不把默认值当成已实读结果。
- `APPLY` 才执行配置。等待当前总线事务结束后，目标板暂停音符资格，进入配置模式，逐项写入和回读，再退出配置；其他板正常采集。全部成功才更新APPLIED。
- `DEFAULT` 只将本板编辑值恢复GSR=02、KOR=04，仍须APPLY。`REINIT` 重新写入最后成功配置。
- 配置错误保留寄存器地址、期望值及读值。后续自动恢复使用最后成功配置，不能因部分写入就宣称成功。错误31表示配置命令等待就绪/完成超时。
- 参数仅本次运行有效；断线重连保留，系统复位或断电恢复默认，不占用曲库Flash。
- 建立基线/重初始化时手应离开电极。三板当前2/4是相同起点，不是实物校准结果。第二板背面轻托触发不能仅靠数字过滤保证消除，需要结合阈值、供电、共地、参考电容和安装环境实测。

### 总览与通信字段

每行末尾8位数字表示一个32位十六进制字。`PCB CH TAB PAGE` 从左到右为板号、通道、子页、详情页各1字节。生产构建标识与源码哈希见交付manifest；页面标题为PCB DEBUG / MUTED，右上BUILD 26102801与交付manifest对应。

`ONLINE VALID MUTE` 的位9为诊断跨域有效，位8为最终静音确认，位7..5为三板数据有效，位4..2为三板通信在线，位1为配置等待，位0为冻结。通信在线只表示配置/通信健康，不能用它代替按键数据新鲜度。

`STATE CFG FAIL IN` 低16位：bit15保留，bit14配置完成，bit13正在应用，bit12数据有效，bit11通信在线，bit10通信/配置故障，bit9..8连续通信失败数，bit7..3初始化索引，bit2..1读字节索引，bit0为同步INT。

`LAST ERROR BYTES` 从高到低为最后故障原因、寄存器、期望字节、实际字节。原因11=NACK，12=总线/时钟超时，14=50ms无一致数据，21=配置写失败，22=配置读失败，23=配置回读不符，2F=非法状态恢复。这些原因与App中的Flash错误码属于不同模块。自动恢复成功仍保留最后故障的地址和比较值，当前故障是否仍存在看STATE及VALID；健康时CLEAR才清除此历史故障字。合法双读变化单独以事件13和计数记录，不覆盖故障字。诊断bit609表示曾完成整板全部配置验证，bit592..608分别表示当前GSR和16路KOR回读已验证。

`GOOD CHANGED` 高16位为变化次数、低16位为一致快照次数；`NACK TIMEOUT` 高16位为超时、低16位为NACK；`REINIT STALE` 高16位为数据过期、低16位为重新初始化。计数到FFFF饱和。`LAST GOOD MS` 和 `AGE MS` 单位为毫秒。

BUS的 `I2C STATE/PINS` 低32位：bit0错误、bit1忙、bit2 SDA主动拉低、bit3 SCL主动拉低、bit4 SDA同步输入、bit5 SCL同步输入、bit6重复起始、bit7读操作、bit10..8位索引、bit13..11事务阶段、bit18..14总线状态、bit26..19最近接收字节，bit31..27发送字节低5位。高32位补充发送字节高3位、寄存器地址、等待计数低8位和错误码；详细位定义以模块diagnostic拼接为准。1ms采集总线现场，100ms刷新页面；单周期事件由计数和历史保留。

BUS详情页1显示最近4条事件，页2显示前4条；每条为 `{毫秒低16位,原因8位,寄存器8位}`，最新在前。不能从SDA/SCL数字状态推断模拟上升时间或供电电压。

### 按键与旋钮链路

KEYS显示两遍原始键值、稳定/候选位图、选中板12键的重武装/路由位图（包含第三板最高四键）、VIEW详情中的全部36键重武装位图、菜单/蓝牙/曲谱屏蔽、音符valid/ready、频率字、持有声部位图及全局音符/PCM计数。菜单内没有新Note On是原有屏蔽策略，不能据此判断I²C或音源故障。

键值两遍变化只增加变化统计和重试，不再作为通信掉线。按下与释放需两次一致快照确认，正常3ms轮询通常增加约一个轮询间隔；极短于确认窗口的触摸可能不被接受。50ms没有一致快照时停止该板音符资格，通信在线单独保留。恢复、退出菜单或重新连接后，持键仍须先松开再按，防止旧键自动重响。

EC11低16位诊断为：bit0双击脉冲、bit1单击、bit2向下、bit3向上、bit5..4上次AB、bit7..6稳定AB、bit10..8同步A/B/SW、bit13..11原始A/B/SW。接着bit16按钮稳定值、bit17按住旋转标志、bit19..18点击状态、bit23..20部分步数、bit31..24点击等待毫秒低8位，bit47..32按住毫秒。其余五个16位饱和计数由低到高为上转、下转、单击、双击、非法跳变。

EC11主页还显示实际效果掩码、回声毫秒、颤音速度、当前编辑项、音量及三个强度目标。CFG ACCEPT/APPLY低16位为请求被接受次数，高16位为系数应用次数，均饱和计数，保留单拍握手；它们是全局效果链计数，不归因于某一旋钮，也不随单板CLEAR清零。

EC11详情页1/2分别显示最新/较早4条关联事件，覆盖旋钮事件和PCB在线变化。事件包括毫秒时间、事件类型及对应状态；61/62分别记录全局效果请求接受/系数应用，其他板事件按对应板记录；它用于定位联动发生在哪一层，不预先认定是接线故障。

蓝牙软复位后的效果恢复已增加回归：在引擎复位撤销后重新提交当前目标，避免恢复脉冲被同拍复位吞掉而停留在默认系数。左右两套真实效果状态均已核对。

## Flash链路

按Flash交接移植整条链路：诊断空闲时实际探测、SAVE/DELETE先刷新、任务中诊断不抢占、LOAD不依赖写权限、取消EF4018单厂商白名单、真实WEL/BUSY与页/整扇区读回。新增probe_error保留真实探测错误，不覆盖历史任务结果。

App版本0.3.3-pcb-flash-debug，versionCode6。任务等待180秒，单请求仍2秒；超时保留任务编号，提示结果未知，不自动重新擦写。RAM下载完成与Flash持久保存分别显示。

U7继续为CS=L25、CLK=P20、MOSI=R21、MISO=T22、WP=R22、HOLD=R20，1MHz/Mode0/24位地址，区域000000至21FFFF。不自动清保护、解锁或整片擦除。有效JEDEC只表示允许尝试现有标准NOR协议，不表示所有实物芯片已经适配。

## 实板核验顺序

1. 核对交付manifest和.fs哈希后由用户烧录；本任务不执行硬件编程。确认页面入口与构建标识一致。
2. 不接触电极完成启动，进入PCB页记录三板ONLINE/VALID、配置回读、NACK/超时和原始位图。
3. 转动旋钮1，观察旋钮计数是否增加、PCB1是否真正通信失败；若只有数据变化/过期，按该路径分析，不能把它写成物理断线。
4. 每板逐通道调KOR，APPLY成功后退出页面演奏；记录按下、松开、和弦、背面轻托及供电环境。先验证一板，再三板同时验证。
5. App读取Flash诊断并保存短曲，等待明确持久确认，再断电载入；再测满容量及替换。只更新App而未更新FPGA不会替换旧驱动。
6. 相同音量下试听1/4/8/16声部和效果旁路/叠加。数字回归通过仍不能替代功放、扬声器及供电实测。
