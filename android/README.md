# 高山流水曲谱 · 安卓开发版 0.2

本目录移植自原手机端开发项目。本轮按用户确认合并实施P0/P1，并将“仅连接蓝牙模块”和“验证FPGA通信”分成两个手动验证入口。APK已重新构建，36043项核心检查与32项连接生命周期检查通过。随后用户已确认实际连接、通信、MIDI文件下载播放、暂停和停止正常；这是用户定性反馈，不覆盖继续、自然结束、断线或长期验收。当前FPGA已接入v1协议，工程边界见[实施说明](../docs/bluetooth_score/实施说明.md)。

## 先验证连接与握手

1. 安装 `dist/GaoshanScore-0.2-dev.apk`。新开发签名与旧0.1不同，需要先卸载旧版再安装；旧版不保存用户曲谱库。新签名密钥保留在本机忽略的build-local/connection目录，不对外分发。
2. 允许附近设备权限；本版会停止系统蓝牙发现以减少建连干扰，但不主动扫描周边设备。若仅授权连接，也会提示跳过停止扫描并继续尝试。
3. 第一步点“连接蓝牙模块”，选择已配对模块。默认先安全RFCOMM，失败并关闭旧Socket后尝试insecure兼容连接，每次最多12秒。也可在连接方式中单独选择一种模式作对照。
4. 界面显示“模块已连接 · FPGA尚未验证”后，先观察模块实际连接状态、保持、断开和重连。这一步不会发送HELLO或其他应用层协议字节，不以FPGA应答作为连接成功条件。
5. 第二步手动点“验证FPGA通信（HELLO）”。正确HELLO后再GET_STATUS，显示设备能力和真实状态，随后开放下载/播放控制。
6. HELLO失败但Socket仍正常时保留模块连接，可再次点击验证；真正EOF、读写失败或连接关闭则显示未连接，并关闭设备操作入口。不会无限自动重试或把握手失败冒充建连失败。
7. 若仍不能连接，点“复制诊断记录”。记录包含版本、设备、连接模式、阶段、时间、异常以及握手TX/RX摘要；详细异常堆栈同时写入Gaoshan-SPP的Android日志。记录仅本地展示/复制，不上传。

用户已确认当前 App 可以连接模块并完成通信与曲谱下载。连接/断开10轮和异常恢复仍属后续验收；测试时先关闭其他串口软件对该模块的连接。

## 手机界面与操作

1. 可以先点“离线演示”。顶部明确显示“离线演示 · 未连接FPGA”；能力来自手机内参考模拟器，不是实测。
2. 点“三音符示例”，得到C4/D4/E4、力度100、时长1900ms的黄金曲谱；或者用系统文件选择器导入.mid/.midi。
3. 导入后选择全部或单一轨道、全部或单一通道、-48～+48半音移调；点“应用筛选与移调”。无需输入电脑路径。
4. 查看音符数、时长、最大同时发声数、MIDI音域、数据大小、CRC32。遇到被忽略控制器时会显示“简化演奏”提示，并在下载确认中列出。
5. 点“下载到琴”，确认替换原曲。进度只随确认的记录数前进；100%数据已传不等于完成，COMMIT与时长核对后才显示成功。
6. 播放/暂停/继续/停止后查询一次设备状态；也可点“刷新设备状态”。查询间隔至少500ms。暂停的实际行为由FPGA实施，模拟模式只演示协议状态。
7. 离线演示不通过Android音频系统发声，不驱动FPGA；它不是音质试听或链路测试。

## 后续真实连接

- 在系统设置中配对经典蓝牙SPP模块，再点“选择蓝牙设备”；App不扫描周边设备，不要求位置权限，不支持BLE串口。
- Android12及以上按系统提示授予“附近设备”连接与扫描控制权限；扫描权限用于cancelDiscovery，不启动设备发现、不申请定位。拒绝连接权限后可用离线演示，也可在系统设置修改权限。
- 固定SPP UUID 00001101-0000-1000-8000-00805F9B34FB；模块固件是否提供该服务仍需实物确认。
- 手机SPP没有UART波特率设置；模块已由用户确认数据模式9600bit/s，FPGA UART须相同。HELLO显示FPGA报告的配置，不自动发送AT指令。
- “真实蓝牙 · HELLO已确认”只会在完整HELLO成功后出现。本分支 FPGA 已实现 HELLO/下载/播放，生产配置声明 1024 条记录、1 个自动声部；用户已确认 EC05 实际连接及通信正常，协议仿真本身不代表无线连接成功。
- App当前面向前台使用，无前台服务或后台持续传输承诺。关闭Activity将关闭socket；重新连接必须HELLO并从头上传。
- 如中断时设备仍在上传，固件须按协议30秒清理，或下次HELLO立即清理；手机不能假装已经恢复旧曲。

## MIDI支持边界

- 标准MIDI Format0/1、PPQN；默认500000μs/四分音符；Format1全局合并速度图，筛选轨道仍保留全曲速度图。
- 支持变长delta、running status、Note On/Off、velocity0结束、通道+音高FIFO配对的同音高重叠。
- 以整数精确累积速度/时间，开始和结束分别取最近毫秒，0.5ms向上；按起音时间排序，相同起音保留原先稳定次序。
- 支持全部或单一轨道、全部或单一通道；暂不支持任意多选组合或自动提取主旋律。
- 忽略踏板、弯音、程序/表情等控制，检测后必须确认简化；不宣称还原原MIDI音色。
- 拒绝Format2、SMPTE、缺失配对、非法长度、冲突速度、舍入后零时长、音符超过65535ms、协议总时长/音域超限等；不静默截断或丢音。
- 文件最大2MiB，音符/速度事件最多100000；设备容量来自HELLO，不能将模拟器的1024条/4声部/MIDI48～83当成实板能力。
- 不支持PDF、图片、MP3识谱、在线曲库或账户系统。歌曲名留在手机，不通过v1传输。

## 协议实现

纯Java核心位于app/src/main/java/cn/whu/gaoshan/core。
Wire负责小端帧、CRC16/CRC32、拆帧/粘帧与超时；ProtocolClient负责HELLO、停等序号、最多4次相同请求、响应匹配、16记录分包、ABORT与播放命令；Score负责容量/音域/最大重叠检查；MidiFile负责转换；SimulatedDevice只用于离线参考演示。

只有一条后台工作队列可以提交命令。接收线程持续读socket，4096字节队列溢出或EOF明确使会话失败。写入看门狗10秒、连接超时15秒；响应每次2秒，最多4次发送。断开按钮直接关闭socket，不等待工作队列。
错误业务响应消耗普通序号；SEQ_CONFLICT/版本/内部错误及响应耗尽会使协议会话失效，须重新HELLO；蓝牙链路仍正常时可点第二步重验，真实链路故障才需重连。改参数不能复用旧SEQ。取消在当前帧完成后发ABORT，通信失败时不谎报已取消琴端事务。

模拟器不是完整FPGA规范实现：它没有UART采样、RF链路、30秒上传超时、真实ADSR尾音或真实音频，也不证明GPIO/CDC/STA正确。
